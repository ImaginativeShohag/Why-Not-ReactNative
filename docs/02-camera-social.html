02 · Camera & Social Capture

A capture-edit-share app. Camera preview with modes, a gesture-driven photo editor, a media grid, and full inbound/outbound sharing with the OS.

Why this one second

Project 01 never left the sandbox. It's also where Reanimated stops being decoration and becomes the only way to build a 60fps editor.

UI design & screens

Design language

  • Tone: media-first and dark by default. Chrome is translucent (blur) and floats over content; the photo is never letterboxed by UI.
  • Camera screen owns the full display including under the status bar. Controls sit in safe-area-aware overlays.
  • Immediate feedback: shutter → haptic + flash animation + thumbnail fly-to-corner. Latency perception matters more than actual latency here.
  • Gestures over buttons where natural: pinch to zoom, double-tap to flip, swipe up for the gallery, swipe between modes.

The mode strip, the limited-access banner, and the EXIF panel are the three details that separate a demo from something that feels native.

Interaction details worth building properly

  • Shutter feedback chain: haptic impact → white flash overlay (150 ms) → captured thumbnail scales down and flies to the corner button. All on the UI thread via Reanimated.
  • Pinch-to-zoom on the camera mapped to the camera's zoom range with a non-linear curve — linear mapping feels wrong.
  • Tap-to-focus with a shrinking ring at the tap point that fades after ~1s.
  • Mode strip that snaps between Photo/Video/Scan, with the shutter morphing shape per mode (circle → red rounded square → hidden).
  • Shared-element transition from the grid thumbnail into the full viewer. Expo Router supports shared transitions on native stacks — try it, and have a cross-fade fallback.
  • Swipe-down-to-dismiss the viewer with the background opacity tracking the drag distance.
  • Crop overlay: simultaneous pinch + pan + rotate composed with Gesture Handler's Gesture.Simultaneous, with clamping so the image can never leave the crop frame.

Key architectural decision: the editor as an operation list

Do not mutate the image on every gesture. Instead:

EditorState = {
  sourceUri: string
  operations: Op[]        // [{crop}, {rotate:90}, {filter:'mono', intensity:0.7}]
  cursor: number          // for undo/redo
}

Preview  → render sourceUri with a live GPU transform (Skia / animated style)
Commit   → run operations sequentially through the image manipulator,
           write a new file, return its uri

This gives you free undo/redo, a cheap preview, non-destructive editing, and one obvious place to unit-test. It's also how every real editor works.

The media pipeline

CAPTURE
  CameraView.takePictureAsync({ quality, exif, skipProcessing? })
     └─► temp file uri in cache directory

INGEST
  copy/move into app document dir  (expo-file-system File API)
  extract EXIF + dimensions
  generate thumbnail (manipulator resize → ~400px, jpeg q0.7)
  insert row in local db (reuse Project 01's SQLite skills)

EDIT
  operations[] applied → new derived file
  original preserved (non-destructive)

EXPORT
  compress to target size/format
  optionally save to device gallery (MediaLibrary.Asset.create / saveToLibraryAsync)
  or hand a uri to expo-sharing
Never move pixels through JS

Reading image bytes into a JS array to "apply a filter" will kill you on a 12MP photo. Filters belong on the GPU (Skia shaders / color matrices) or in a native manipulator call. If you find yourself writing a per-pixel loop in JS, stop.

Build order

M0 Dev build first

Goal: get off Expo Go before you need to.
  • eas build --profile development --platform ios --local (and Android).
  • Install on a physical device — the simulator camera is useless for this project.
  • Confirm hot reload works against the dev client.
Checkpoint — You can add a native dependency, rebuild, and be running again in under 15 minutes.

M1 Camera preview & permissions

Goal: a working preview with a real permission flow.
  • CameraView full-bleed with useCameraPermissions.
  • The <PermissionGate> component: rationale → prompt → blocked-with-Settings-link.
  • Flip camera, flash mode cycling, torch toggle.
  • Configure the permission usage strings via the expo-camera config plugin in app.json, not by hand-editing Info.plist.
Checkpoint — Deny permission in Settings, relaunch, and the app explains itself instead of showing a black rectangle.

M2 Capture & the feedback chain

Goal: taking a photo feels instant.
  • takePictureAsync → ingest into the app directory → thumbnail → local DB row.
  • Shutter animation, haptic, flash overlay, fly-to-corner thumbnail — all Reanimated on the UI thread.
  • Pinch-to-zoom and tap-to-focus.
  • Feed grid showing captures, newest first.
Checkpoint — Fire the shutter 10 times rapidly. No dropped captures, no frozen UI, no memory warning.

M3 Media library

Goal: browse the device's photos properly.
  • Paginated asset reads (getAssetsAsync with after cursor) into a FlashList grid.
  • Album picker.
  • Multi-select with a selection bar.
  • iOS limited-access: detect it, show the banner, offer presentPermissionsPickerAsync.
  • Video assets show a duration badge and a play affordance.
Checkpoint — Test on a device with 5,000+ photos. Scrolling stays smooth and memory doesn't climb without bound.

M4 The editor

Goal: a crop/rotate/filter editor with undo.
  • Operation-list state + undo/redo.
  • Crop overlay: composed pinch/pan/rotate gestures with clamping; aspect-ratio presets.
  • Live preview via animated transforms — no re-encoding per frame.
  • Filter strip: color-matrix filters rendered with Skia (or a simple overlay approach as a fallback).
  • Commit: apply operations through expo-image-manipulator, write the derived file.
Checkpoint — Apply crop → rotate → filter, undo all three, redo all three, save. The output matches the preview exactly. Preview/output mismatch is the classic editor bug.

M5 Viewer & transitions

Goal: the polish layer.
  • Full-screen viewer with pinch-zoom, double-tap zoom, and pan-when-zoomed.
  • Swipe-down-to-dismiss with progressive background fade.
  • Shared-element transition from the grid (with a graceful fallback).
  • Horizontal paging between posts.
  • EXIF metadata panel.
Checkpoint — Zoom in hard on a 12MP image and pan. It stays smooth and sharp.

M6 Sharing, both directions

Goal: your app is a citizen of the OS.
  • Share out: expo-sharing to the system sheet; copy to clipboard with expo-clipboard.
  • Save to the device gallery with a dedicated album.
  • Deep links: whynotreactnative://post/123 and an https universal link. Test cold start, warm start, and background.
  • Inbound share: add a share extension via a config plugin (e.g. expo-share-intent) so photos can be shared into your app.
Checkpoint — From Apple Photos, share a photo into your app; it opens on the inbound screen with the asset ready to edit. This is the milestone that teaches you what config plugins are for.

M7 Video

Goal: the second media type, which breaks half your assumptions.
  • Record with recordAsync, with a max duration and a progress ring.
  • Microphone permission (separate from camera).
  • Playback with expo-video's VideoView + useVideoPlayer.
  • Thumbnail generation for the grid.
  • A simple trim UI with a scrubbable filmstrip.
Checkpoint — Record 60 s, background the app mid-recording, return. You handle it (either stop cleanly or continue) rather than crashing.

Failure modes to experience deliberately

  1. The permission dead-end. Deny camera access, then try to open the camera screen. If your app shows a black view with no explanation, you've shipped the most common RN bug in the App Store.
  2. Camera not released. Navigate away from the camera without deactivating it; battery drains and the preview freezes on return. Use the active prop tied to screen focus (useIsFocused).
  3. Cache directory eviction. Save a capture's uri from the cache directory into your DB, come back a week later — the file is gone. Always copy into the document directory on ingest.
  4. Orientation/EXIF rotation. A photo shot in landscape displays sideways after manipulation because you stripped EXIF orientation. Learn to normalize rotation at ingest.
  5. OOM on large images. Load ten 48MP originals into a grid at full resolution. Watch it die. Then fix it with thumbnails and recyclingKey.
  6. Gesture conflicts. A pinch inside a scrollable that also pans — without simultaneousWithExternalGesture one of them wins and the UX feels broken.
  7. Preview ≠ output. Your crop preview uses screen coordinates; the manipulator uses source-pixel coordinates. Get the transform math wrong and the saved crop is offset. This will happen; the fix is deriving both from one normalized rect.
  8. Android scoped storage. Writing to the gallery behaves differently across Android versions. Test on both an older and a newer device/emulator.

Stretch goals

  • Frame processors with Vision Camera + a face/object detector running at 30 fps on the frame stream, no JS involvement.
  • Custom Skia shaders for filters — write actual SkSL.
  • Live QR scanner with an overlay that highlights detected code bounds in real time.
  • Background upload of captures with resumable uploads and progress notifications.
  • Photo picker without permission — on modern Android/iOS the system picker requires no permission at all. Implement both paths and compare the UX.
