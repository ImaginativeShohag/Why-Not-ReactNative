Why this one first

Almost every RN tutorial starts by fetching from an API, which teaches you to treat the network as the source of truth. That habit produces apps that spin forever in a tunnel. Starting local-first inverts the model: the device is the source of truth, and the server is a replica you reconcile with. Everything else in this path is easier once you think that way.

How to use this page

This is a build-along tutorial for a finished app. Every snippet is a whole file from the repo, with its real path and imports, written against Expo SDK 57 / RN 0.86 and the repo's conventions (@/src/… aliases, double quotes, ThemedText from src/shared/). They use plain expo-sqlite; the Drizzle variant is shown once, as an optional path you do not need.

Work through the milestones in order. At each one: read the goal, type the files out (do not paste), run the Verify commands, and pass the Checkpoint before moving on. When something looks arbitrary — the WHERE entries.dirty = 0 in the pull merge, the next_attempt_at column, the module-scope defineTask, the payload = ? in completeItem — stop there. Those lines are the lesson. Afterwards, open docs/training/index.html and take the Project 01 quiz: each question sends you to the real file to confirm what you built.

Learning objectives

By the end you will have built an app whose database is the source of truth, whose writes are atomic with their sync intent, and whose every network, OS and lifecycle dependency is treated as unreliable.

UI design & screens

Design language

  • Tone: calm, paper-like, content-forward. Generous whitespace, one accent colour, serif for entry body text and sans for chrome.
  • Density: the timeline is the app. Everything else is a modal or a sheet over it.
  • Themes: full light/dark support driven by useColorScheme, plus a user override stored locally (system / light / dark) — this repo's themed-text / themed-view pattern already gives you the base.
  • Motion: subtle only. Entry insert/delete uses layout animation; nothing bounces.

Interaction details worth building properly

  • Autosave: debounce ~800 ms, save the entry row itself (there is no separate drafts table: a draft is just a dirty entry), show a quiet "Saved HH:MM ✓". Never a spinner.
  • Swipe to delete on a timeline row, using Gesture Handler's ReanimatedSwipeable — with an undo snackbar rather than a confirm dialog.
  • Sticky day headers in FlashList, driven by section data rather than a separate SectionList.
  • Optimistic delete: the row animates out immediately; the DB delete happens after the undo window expires.
  • Keyboard handling: the compose toolbar must sit on the keyboard, not behind it. Use KeyboardAvoidingView with the header height as the offset (useHeaderHeight from expo-router/react-navigation). react-native-keyboard-controller is a smoother option if you outgrow it.
  • Empty states: first launch, no search results, and a filtered day with nothing in it are three different empty states with three different messages.

What is not in this list

No components/ui/ for generic primitives — themed-text, themed-view, icon-symbol and content-unavailable-view already live in src/shared/components/. Import them; don't re-make them. Conversely, EntryCard and MoodPicker are journal-specific and stay in the slice no matter how reusable they look. Promote to shared/ only when a second project needs the thing.

db/, sync/ and reminders/ aren't in the standard slice subfolder list, and that's fine — the list is a floor, not a cage. A project adds the folders its domain needs; what it must not do is scatter them outside the slice.

Layer rules

  • db/queries/* are pure functions of the db handle. No React, no stores. This makes them unit-testable without a renderer.
  • hooks/* are the only place that binds queries to React (via a live-query hook or TanStack Query with a local query function).
  • Components never import a store or a db module. Props and callbacks only — same discipline you apply to SwiftUI subviews.
  • The sync task is defined at module scope and imported from the root layout (not the journal's). Project layouts only load when the user opens that project, so a headless background launch would never define the task.
  • sync/policy.ts is pure: no db, no network, no clock you cannot inject. Every sync decision lives there, and the engine only applies it.
  • Non-React callers (the sync engine, the background task) get the database from getDb(); screens and hooks only use useSQLiteContext().
  • Nothing in this slice imports from src/projects/store/, and nothing there imports from here. The journal has its own query keys, its own models, its own stores.
  • Every non-route file lives under src/projects/offline-journal/. LockGate is a component, not a destination — parking it under src/app/ would create a real /projects/offline-journal/LockGate route.

/**
 * The DB open + migration can throw (a bad migration, a full disk). Without a
 * boundary that is a red screen; with one it is a message and a retry.
 */
class DatabaseErrorBoundary extends Component<
  { children: ReactNode },
  { error: Error | null }
> {
  state = { error: null as Error | null };

  static getDerivedStateFromError(error: Error) {
    return { error };
  }

  render() {
    if (!this.state.error) return this.props.children;
    return (
      <View style={styles.center}>
        <ThemedText type="subtitle">Could not open the journal</ThemedText>
        <ThemedText style={styles.error}>{this.state.error.message}</ThemedText>
        <Pressable onPress={() => this.setState({ error: null })}>
          <ThemedText type="link">Try again</ThemedText>
        </Pressable>
      </View>
    );
  }
}

Do not mount a second QueryClientProvider here

Even "for the sync layer only." A second client is a second independent cache — the store project already learned this the hard way when its tab layout mounted one and login-time data was invisible to the tab screens. The global client in src/app/_layout.tsx is the only one.

SQLiteProvider sits inside Suspense (the open is not instant on a cold start with a large file) and inside a DatabaseErrorBoundary: a bad migration or full disk then shows a message and a retry instead of a red screen. Note what JournalStack mounts: useAppLock for the gate, useSyncTriggers exactly once, and a cleanup that re-arms the lock when the user leaves the journal for the launcher.

All four versions in one file. V1 is the base schema, V2 adds search, V3 is the "add a column without losing data" migration (ALTER TABLE … ADD COLUMN is the one change SQLite does in place), and V4 shows how to fix something already shipped: a device that ran V2 never runs it again, so the trigger is replaced by a new step, never by editing V2. Note what is not a helper here: the version gate is a dozen lines of plain code, and it is the piece an ORM hides from you.

src/projects/offline-journal/db/migrations.tsts
import type { SQLiteDatabase } from "expo-sqlite";

export const SCHEMA_VERSION = 4;

const V1 = `
CREATE TABLE entries (
  id          TEXT    PRIMARY KEY NOT NULL,   -- ULID, generated on device
  title       TEXT    NOT NULL DEFAULT '',
  body        TEXT    NOT NULL DEFAULT '',
  mood        INTEGER,                        -- 1..5, null = not set
  created_at  INTEGER NOT NULL,               -- epoch ms
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,                        -- soft delete; hard deletes break sync
  remote_id   TEXT,
  dirty       INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_entries_timeline ON entries (created_at DESC) WHERE deleted_at IS NULL;
CREATE INDEX idx_entries_dirty    ON entries (dirty) WHERE dirty = 1;

CREATE TABLE tags (
  id   TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE entry_tags (
  entry_id TEXT NOT NULL REFERENCES entries (id) ON DELETE CASCADE,
  tag_id   TEXT NOT NULL REFERENCES tags (id)    ON DELETE CASCADE,
  PRIMARY KEY (entry_id, tag_id)
);

CREATE TABLE attachments (
  id       TEXT    PRIMARY KEY NOT NULL,
  entry_id TEXT    NOT NULL REFERENCES entries (id) ON DELETE CASCADE,
  file_uri TEXT    NOT NULL,                  -- the blob lives on disk, not here
  mime     TEXT    NOT NULL,
  width    INTEGER,
  height   INTEGER,
  bytes    INTEGER
);
CREATE INDEX idx_attachments_entry ON attachments (entry_id);

CREATE TABLE outbox (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,   -- FIFO by insertion
  op              TEXT    NOT NULL,                    -- create | update | delete
  entity          TEXT    NOT NULL,
  entity_id       TEXT    NOT NULL,
  payload         TEXT    NOT NULL,                    -- JSON
  attempts        INTEGER NOT NULL DEFAULT 0,
  next_attempt_at INTEGER NOT NULL DEFAULT 0,          -- backoff gate
  last_error      TEXT,
  created_at      INTEGER NOT NULL
);
CREATE INDEX idx_outbox_ready ON outbox (next_attempt_at, id);

CREATE TABLE sync_meta (
  key   TEXT PRIMARY KEY NOT NULL,
  value TEXT
);
`;

const V2 = `
-- External-content FTS5: the index stores no copy of the text, it points at
-- entries.rowid. That is why every write needs a trigger below.
CREATE VIRTUAL TABLE entries_fts USING fts5(
  title, body, content = 'entries', content_rowid = 'rowid'
);

-- Backfill first. Skip this and every pre-existing entry is unsearchable.
INSERT INTO entries_fts (rowid, title, body)
  SELECT rowid, title, body FROM entries;

CREATE TRIGGER entries_ai AFTER INSERT ON entries BEGIN
  INSERT INTO entries_fts (rowid, title, body)
    VALUES (new.rowid, new.title, new.body);
END;

CREATE TRIGGER entries_ad AFTER DELETE ON entries BEGIN
  INSERT INTO entries_fts (entries_fts, rowid, title, body)
    VALUES ('delete', old.rowid, old.title, old.body);
END;

CREATE TRIGGER entries_au AFTER UPDATE ON entries BEGIN
  INSERT INTO entries_fts (entries_fts, rowid, title, body)
    VALUES ('delete', old.rowid, old.title, old.body);
  INSERT INTO entries_fts (rowid, title, body)
    VALUES (new.rowid, new.title, new.body);
END;
`;

// The "do it twice" migration. ALTER TABLE ... ADD COLUMN is the one schema
// change SQLite does in place without a table rebuild, so existing attachment
// rows survive untouched — their new columns are simply NULL until a thumbnail
// is generated.
const V3 = `
ALTER TABLE attachments ADD COLUMN thumb_uri  TEXT;
ALTER TABLE attachments ADD COLUMN blurhash   TEXT;
ALTER TABLE attachments ADD COLUMN created_at INTEGER NOT NULL DEFAULT 0;
`;

// V2 shipped `entries_au` as AFTER UPDATE ON entries, so every bookkeeping
// write — markDone flipping `dirty`, a soft delete, `remote_id` — deleted and
// re-inserted the row in the index for nothing. The index only covers title and
// body, so only those columns need the trigger. V2 is never edited (devices
// already ran it); a shipped trigger is replaced by a new step.
const V4 = `
DROP TRIGGER entries_au;

CREATE TRIGGER entries_au AFTER UPDATE OF title, body ON entries BEGIN
  INSERT INTO entries_fts (entries_fts, rowid, title, body)
    VALUES ('delete', old.rowid, old.title, old.body);
  INSERT INTO entries_fts (rowid, title, body)
    VALUES (new.rowid, new.title, new.body);
END;
`;

};

export async function migrate(db: SQLiteDatabase) {
  // PRAGMAs go outside the transaction: journal_mode cannot change inside one.
  await db.execAsync("PRAGMA journal_mode = WAL");
  await db.execAsync("PRAGMA foreign_keys = ON");

  const row = await db.getFirstAsync<{ user_version: number }>(
    "PRAGMA user_version",
  );
  let version = row?.user_version ?? 0;

  while (version < SCHEMA_VERSION) {
    const next = version + 1;
    // One transaction per step, and the version bump rides inside it — a crash
    // mid-upgrade leaves you on a version that actually matches the schema.
    await db.withTransactionAsync(async () => {
      await db.execAsync(MIGRATIONS[next]);
      await db.execAsync(`PRAGMA user_version = ${next}`); // cannot be a bound param
    });
    version = next;
  }
}

/** Repair tool for when a trigger was missing or wrong. */
export async function rebuildSearchIndex(db: SQLiteDatabase) {
  await db.execAsync(
    "INSERT INTO entries_fts (entries_fts) VALUES ('rebuild')",
  );
}
Four details that bite

PRAGMA journal_mode cannot change inside a transaction, so the PRAGMAs run before the loop. PRAGMA user_version = ? cannot be a bound parameter — it has to be interpolated, which is safe only because the value is a number you control. And the FTS5 table is external content: it stores no copy of the text, so without the three triggers the index silently drifts from the rows. Finally, never edit a shipped migration: add the next number.

import type { Entry, EntryRow, Mood } from "../../models/Entry";
import { ulid } from "../../utils/id";

// Writes
// ---------------------------------------------------------------------------

export type EntryInput = {
  id?: string;
  title: string;
  body: string;
  mood: Mood | null;
  /** Omit to leave the entry's tags untouched. */
  tags?: string[];

/**
 * Row change + outbox row in ONE transaction. This is the whole offline-first
 * trick: they land together or not at all, so the queue can never disagree with
 * the data it is supposed to be shipping.
 */
export async function saveEntry(db: SQLiteDatabase, input: EntryInput) {
  const id = input.id ?? ulid();
  const now = Date.now();
  const tags = input.tags ? normalizeTags(input.tags) : undefined;

  await db.withTransactionAsync(async () => {
    await db.runAsync(
      `INSERT INTO entries (id, title, body, mood, created_at, updated_at, dirty)
       VALUES (?, ?, ?, ?, ?, ?, 1)
       ON CONFLICT (id) DO UPDATE SET
         title      = excluded.title,
         body       = excluded.body,
         mood       = excluded.mood,
         updated_at = excluded.updated_at,
         deleted_at = NULL,
         dirty      = 1`,
      id,
      input.title,
      input.body,
      input.mood,
      now,
      now,
    );

    if (tags) await writeTags(db, id, tags);

    await enqueue(db, input.id ? "update" : "create", id, {
      id,
      title: input.title,
      body: input.body,
      mood: input.mood,
      tags: tags ?? (await tagNames(db, id)),
      updated_at: now,
    });
  });

  return id;
}

/** Soft delete. The row stays so the delete can be replayed to the server. */
export async function softDeleteEntry(db: SQLiteDatabase, id: string) {
  const now = Date.now();

  await db.withTransactionAsync(async () => {
    await db.runAsync(
      "UPDATE entries SET deleted_at = ?, updated_at = ?, dirty = 1 WHERE id = ?",
      now,
      now,
      id,
    );
    await enqueue(db, "delete", id, { id, deleted_at: now });
  });
}

/**
 * Danger zone. Still soft + queued, so the server replicates the wipe.
 *
 * Set-based rather than `softDeleteEntry` per row, so it mirrors `enqueue`'s
 * coalescing in SQL: an unattempted outbox row for the entry becomes the delete
 * (a delete always wins the merge), everything else gets a fresh delete row.
 */
export async function softDeleteAll(db: SQLiteDatabase) {
  const now = Date.now();
  const live = "SELECT id FROM entries WHERE deleted_at IS NULL";
  let count = 0;

  await db.withTransactionAsync(async () => {
    await db.runAsync(
      `UPDATE outbox SET
         op              = 'delete',
         payload         = json_object('id', entity_id, 'deleted_at', ?),
         next_attempt_at = 0
       WHERE id IN (
         SELECT MAX(id) FROM outbox
         WHERE attempts = 0 AND entity_id IN (${live})
         GROUP BY entity_id
       )`,
      now,
    );
    await db.runAsync(
      `INSERT INTO outbox (op, entity, entity_id, payload, created_at)
       SELECT 'delete', 'entry', id, json_object('id', id, 'deleted_at', ?), ?
       FROM entries e
       WHERE e.deleted_at IS NULL
         AND NOT EXISTS (
           SELECT 1 FROM outbox o WHERE o.entity_id = e.id AND o.attempts = 0
         )`,
      now,
      now,
    );
    const result = await db.runAsync(
      "UPDATE entries SET deleted_at = ?, updated_at = ?, dirty = 1 WHERE deleted_at IS NULL",
      now,
      now,
    );
    count = result.changes;
  });

  return count;
}

/**
 * Hard delete of soft-deleted rows. By default only rows whose delete has
 * already reached the server (dirty = 0, nothing queued) — purging earlier
 * would lose the tombstone the server needs. `includeUnsynced` is for when sync
 * is off: there is no server to tell, so the queued deletes go too.
 *
 * Returns the attachment paths that no longer have a row, so the caller can
 * remove the files. Rows first, files second: a crash in between leaves orphan
 * files (swept later), never rows pointing at nothing.
 */
export async function purgeDeleted(
  db: SQLiteDatabase,
  options: { includeUnsynced?: boolean } = {},
) {
  const where = options.includeUnsynced
    ? "deleted_at IS NOT NULL"
    : `deleted_at IS NOT NULL AND dirty = 0
       AND NOT EXISTS (SELECT 1 FROM outbox o WHERE o.entity_id = entries.id)`;

  const doomed = `SELECT id FROM entries WHERE ${where}`;
  const files: string[] = [];
  let purged = 0;

  await db.withTransactionAsync(async () => {
    const attachments = await db.getAllAsync<{
      file_uri: string;
      thumb_uri: string | null;
    }>(
      `SELECT file_uri, thumb_uri FROM attachments WHERE entry_id IN (${doomed})`,
    );
    for (const a of attachments) {
      files.push(a.file_uri);
      if (a.thumb_uri) files.push(a.thumb_uri);
    }
    // Safe to run first: the includeUnsynced `where` does not look at outbox.
    if (options.includeUnsynced)
      await db.runAsync(`DELETE FROM outbox WHERE entity_id IN (${doomed})`);
    // entry_tags and attachments go with it: ON DELETE CASCADE.
    const result = await db.runAsync(`DELETE FROM entries WHERE ${where}`);
    purged = result.changes;
  });

  return { purged, files };
}

And the outbox itself — a table with a backoff column, which is all a retry queue really is. Read completeItem twice: its payload = ? check is what stops a successful response from deleting an edit that was folded in while the request was in flight.

src/projects/offline-journal/db/queries/outbox.tsts
import type { SQLiteDatabase } from "expo-sqlite";

import type { OutboxItem, OutboxOp } from "../../models/Entry";
import { backoffDelay, MAX_ATTEMPTS, mergeOutboxOp } from "../../sync/policy";

export { MAX_ATTEMPTS };

/**
 * Must be called inside the same transaction as the row change it describes.
 *
 * Compaction: if an item for this entity is still waiting and has never been
 * attempted, fold the new op into it instead of queueing another request. An
 * item that has been attempted is left alone — the server may already have
 * seen it, so the new op must follow it in order.
 */
export async function enqueue(
  db: SQLiteDatabase,
  op: OutboxOp,
  entityId: string,
  payload: unknown,
) {
  const waiting = await db.getFirstAsync<{ id: number; op: OutboxOp }>(
    `SELECT id, op FROM outbox
     WHERE entity_id = ? AND attempts = 0
     ORDER BY id DESC LIMIT 1`,
    entityId,
  );

  if (waiting) {
    await db.runAsync(
      "UPDATE outbox SET op = ?, payload = ?, next_attempt_at = 0 WHERE id = ?",
      mergeOutboxOp(waiting.op, op),
      JSON.stringify(payload),
      waiting.id,
    );
    return;
  }

  await db.runAsync(
    `INSERT INTO outbox (op, entity, entity_id, payload, created_at)
     VALUES (?, 'entry', ?, ?, ?)`,
    op,
    entityId,
    JSON.stringify(payload),
    Date.now(),
  );
}

/** Oldest-first, skipping items still inside their backoff window. */
export async function claimBatch(db: SQLiteDatabase, limit = 25) {
  return db.getAllAsync<OutboxItem>(
    `SELECT id, op, entity, entity_id, payload, attempts
     FROM outbox
     WHERE next_attempt_at <= ? AND attempts < ?
     ORDER BY id
     LIMIT ?`,
    Date.now(),
    MAX_ATTEMPTS,
    limit,
  );
}

/**
 * Deletes the item only if its payload is still the one we sent. Compaction
 * may have folded a newer edit into this row while the request was in flight —
 * deleting it then would silently drop that edit.
 */
export async function completeItem(db: SQLiteDatabase, item: OutboxItem) {
  const result = await db.runAsync(
    "DELETE FROM outbox WHERE id = ? AND payload = ?",
    item.id,
    item.payload,
  );
  return result.changes > 0;
}

export async function failItem(
  db: SQLiteDatabase,
  item: OutboxItem,
  message: string,
  options: { permanent?: boolean } = {},
) {
  const attempts = options.permanent ? MAX_ATTEMPTS : item.attempts + 1;

  await db.runAsync(
    "UPDATE outbox SET attempts = ?, next_attempt_at = ?, last_error = ? WHERE id = ?",
    attempts,
    Date.now() + backoffDelay(attempts),
    message,
    item.id,
  );
}

export async function outboxStats(db: SQLiteDatabase) {
  const row = await db.getFirstAsync<{ pending: number; dead: number }>(
    `SELECT SUM(attempts <  ?) AS pending,
            SUM(attempts >= ?) AS dead
     FROM outbox`,
    MAX_ATTEMPTS,
    MAX_ATTEMPTS,
  );
  return { pending: row?.pending ?? 0, dead: row?.dead ?? 0 };
}

/** Dead letters back into the queue — for after the server-side bug is fixed. */
export async function retryDeadLetters(db: SQLiteDatabase) {
  await db.runAsync(
    "UPDATE outbox SET attempts = 0, next_attempt_at = 0, last_error = NULL WHERE attempts >= ?",
    MAX_ATTEMPTS,
  );
}

export async function discardDeadLetters(db: SQLiteDatabase) {
  await db.runAsync("DELETE FROM outbox WHERE attempts >= ?", MAX_ATTEMPTS);
}

export async function getMeta(db: SQLiteDatabase, key: string) {
  const row = await db.getFirstAsync<{ value: string }>(
    "SELECT value FROM sync_meta WHERE key = ?",
    key,
  );
  return row?.value ?? null;
}

  await db.runAsync(

    value,
  );
}

  await db.runAsync("DELETE FROM sync_meta WHERE key = ?", key);

Two viable designs — build the first, then try the second and compare:

  1. Live query. A hook that subscribes to DB change events and re-runs its query. Simplest mental model; you can build it yourself on top of addDatabaseChangeListener, or use Drizzle's live-query helper. import {
  addDatabaseChangeListener,
  useSQLiteContext,
  type SQLiteDatabase,
} from "expo-sqlite";
import { useEffect, useState } from "react";

/**
 * Build this before reaching for a library version. Runs `select` once, then
 * re-runs it whenever one of `tables` changes.
 *
 * `select` must be a stable reference (module-level function or useCallback) —
 * a fresh arrow function per render re-subscribes on every render.
 */
export function useLiveQuery<T>(
  tables: readonly string[],
  select: (db: SQLiteDatabase) => Promise<T>,
  initial: T,
) {
  const db = useSQLiteContext();
  const [data, setData] = useState<T>(initial);
  const [error, setError] = useState<Error | null>(null);
  // Distinguishes "still loading" from "loaded, and the answer is empty/null" —
  // the detail screen needs that to tell a spinner from a not-found state.
  const [loaded, setLoaded] = useState(false);
  const watched = tables.join(",");
  // The change listener is process-global: every database opened with
  // `enableChangeListener` (fitness, on every GPS point it stores) emits through
  // it. Table names alone only work until another project adds a `tags` table,
  // so match the file too. By basename, not full path: SQLite reports the path
  // it resolved (on iOS `/private/var/…` for `/var/…`), not the one we passed.
  const file = basename(db.databasePath);

  useEffect(() => {
    let cancelled = false;
    let timer: ReturnType<typeof setTimeout> | null = null;

    const load = () => {
      select(db)
        .then((next) => {
          if (cancelled) return;
          setData(next);
          setError(null);
          setLoaded(true);
        })
        .catch((cause) => {
          if (cancelled) return;
          setError(cause as Error);
          setLoaded(true);
        });
    };

    load();

    const subscription = addDatabaseChangeListener((event) => {
      if (basename(event.databaseFilePath) !== file) return;
      if (!watched.split(",").includes(event.tableName)) return;
      // A transaction fires one event per changed row — coalesce the burst.
      if (timer) clearTimeout(timer);
      timer = setTimeout(load, 50);
    });

    return () => {
      cancelled = true;
      if (timer) clearTimeout(timer);
      subscription.remove();
    };
  }, [db, select, watched, file]);

  return { data, error, loaded };
}

Sync semantics to decide (and write down)

  • Conflict rule: last-write-wins by updated_at? Or field-level merge? LWW is fine here — but state it explicitly.
  • Idempotency: the client-generated ULID is the idempotency key. The server must upsert on it.
  • Backoff: exponential with jitter, capped at five minutes. Cap the attempt count (6) and dead-letter after that. 408 and 429 are retried; every other 4xx is dead-lettered because the server will never accept that payload.
  • Dead letters are surfaced, not hidden: Settings offers retry and discard.
  • Never trust the wire: validate pull responses and drop malformed rows rather than poison the database.
  • Clock skew: never trust the device clock for ordering across devices. Use a server-assigned version/lamport counter if you go multi-device.

import { createServer } from "node:http";

const entries = new Map(); // id -> row; deletes stay as tombstones
const seen = new Set();    // idempotency keys already applied

createServer(async (req, res) => {
  const url = new URL(req.url, "http://localhost");
  const send = (status, body) => {
    res.writeHead(status, { "content-type": "application/json" });
    res.end(JSON.stringify(body));
  };

  if (req.method === "GET" && url.pathname === "/entries") {
    const since = Number(url.searchParams.get("since") ?? 0);
    const rows = [...entries.values()].filter((row) => row.server_at > since);
    return send(200, { entries: rows, serverTime: Date.now() });
  }

  const match = url.pathname.match(/^\/entries\/([^/]+)$/);
  if (!match) return send(404, {});
  const id = decodeURIComponent(match[1]);

  if (req.method === "PUT") {
    let raw = "";
    for await (const chunk of req) raw += chunk;
    const body = JSON.parse(raw);
    if (typeof body.title !== "string") return send(422, { error: "title required" });
    seen.add(req.headers["idempotency-key"]);
    const old = entries.get(id);
    entries.set(id, {
      created_at: body.updated_at, deleted_at: null, ...old, ...body,
      id, server_at: Date.now(),
    });
    return send(200, entries.get(id));
  }

  if (req.method === "DELETE") {
    const old = entries.get(id);
    entries.set(id, { ...(old ?? { id, title: "", body: "", mood: null, created_at: 0 }),
      updated_at: Date.now(), deleted_at: Date.now(), server_at: Date.now() });
    return send(200, {});
  }

  send(405, {});
}).listen(3000, () => console.log("journal mock on :3000"));

import { openDatabaseAsync, type SQLiteDatabase } from "expo-sqlite";

import { migrate } from "./migrations";

export const DATABASE_NAME = "journal.db";

let migrated: Promise<void> | null = null;
let dbPromise: Promise<SQLiteDatabase> | null = null;

/**
 * Runs the schema migrations at most once per process, whichever path gets
 * there first: SQLiteProvider's `onInit` or `getDb()` from a headless sync.
 * Both handles share one native connection (same name, same options), so two
 * overlapping `migrate` calls would collide on BEGIN. A failure clears the
 * memo so the next caller retries.
 */
export function migrateOnce(db: SQLiteDatabase): Promise<void> {
  migrated ??= migrate(db).catch((error) => {
    migrated = null;
    throw error;
  });
  return migrated;
}

/**
 * A lazy handle for the callers that have no React tree: the sync engine and
 * the background task. Nothing is opened until the first sync actually runs,
 * so a cold launch that never touches the journal never opens its database.
 * Screens and hooks must use `useSQLiteContext()` instead.
 *
 * `enableChangeListener` is what makes `addDatabaseChangeListener` fire — and
 * matching SQLiteProvider's options is what lets both reuse one connection.
 */
export function getDb(): Promise<SQLiteDatabase> {
  if (!dbPromise) {
    dbPromise = (async () => {
      const db = await openDatabaseAsync(DATABASE_NAME, {
        enableChangeListener: true,
      });
      await migrateOnce(db);
      return db;
    })().catch((error) => {
      dbPromise = null;
      throw error;
    });
  }
  return dbPromise;
}
Two ways in, one connection — deliberately

SQLiteProvider opens the database for the React tree and getDb() opens it lazily for the sync engine and the background task. With the same name and the same options, expo-sqlite hands both the same native connection, so a write from the sync engine wakes the live queries in your screens (both pass enableChangeListener). Because they share a connection, two overlapping migrate() calls would collide on BEGIN; migrateOnce() memoizes the promise (and clears it on failure so a retry works). What is not fine is a screen calling getDb(): it would bypass Suspense and the error boundary. getDb() is lazy so a cold launch that never touches the journal never opens its database.

src/projects/offline-journal/utils/id.tsts
import { getRandomBytes } from "expo-crypto";

const ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"; // Crockford base32: no I, L, O, U

/**
 * 26-char ULID: 10 chars of millisecond timestamp + 16 chars of randomness.
 * Sorting by id sorts by creation time, which keeps logs and debugging readable.
 * The 80 random bits let any device mint one with no coordination, so the id
 * doubles as the sync idempotency key. The timeline does not page on it:
 * `listEntries` orders by `created_at` and pages with LIMIT/OFFSET.
 *
 * `randomBytes` is injectable so tests can run without the native module.
 */
export function ulid(
  now: number = Date.now(),
  randomBytes: (count: number) => Uint8Array = getRandomBytes,
): string {
  let time = "";
  let remaining = now;
  for (let i = 0; i < 10; i++) {
    time = ALPHABET[remaining % 32] + time;
    remaining = Math.floor(remaining / 32);
  }

  const bytes = randomBytes(16);
  let random = "";
  for (let i = 0; i < 16; i++) random += ALPHABET[bytes[i] % 32]; // 256 % 32 === 0, no bias

  return time + random;
}

/** Recovers the creation time from the first 10 chars. Handy in tests and debugging. */
export function ulidTime(id: string): number {
  let time = 0;
  for (const char of id.slice(0, 10)) time = time * 32 + ALPHABET.indexOf(char);
  return time;
}

  ["work"],
  [],
  ["work", "sync"],
  ["home"],
  ["books"],

const SEEDED_KEY = "seeded_at";

/**
 * Inserts `count` fake entries spread over the last `count` days. Rows are
 * written with dirty = 0 and no outbox rows: seeds are local furniture, not user
 * edits, and must never flood the sync queue.
 */
export async function seedEntries(db: SQLiteDatabase, count = 30) {
  const now = Date.now();
  await db.withTransactionAsync(async () => {
    for (let i = 0; i < count; i++) {
      const createdAt =
        now - i * DAY_MS - Math.floor(Math.random() * DAY_MS * 0.5);
      const id = ulid(createdAt);
      const pick = i % TITLES.length;
      await db.runAsync(
        `INSERT INTO entries (id, title, body, mood, created_at, updated_at, dirty)
         VALUES (?, ?, ?, ?, ?, ?, 0)`,
        id,
        TITLES[pick],
        BODIES[pick],
        (i % 5) + 1,
        createdAt,
        createdAt,
      );
      await writeTags(db, id, TAGS[pick]);
    }
  });
  return count;
}

/**
 * First launch only. Gated on a sync_meta flag rather than "is the table
 * empty?" — otherwise a user who deletes everything gets the fake entries back
 * on the next cold start.
 */
export async function seedOnce(db: SQLiteDatabase, count = 30) {
  if (await getMeta(db, SEEDED_KEY)) return 0;
  const row = await db.getFirstAsync<{ n: number }>(
    "SELECT COUNT(*) AS n FROM entries",
  );
  const inserted = (row?.n ?? 0) > 0 ? 0 : await seedEntries(db, count);
  await setMeta(db, SEEDED_KEY, String(Date.now()));
  return inserted;
}

import type { Entry } from "../models/Entry";
import { DAY_MS, dayKey } from "./date";

export type TimelineRow =
  | { kind: "header"; key: string; label: string }
  | { kind: "entry"; key: string; entry: Entry };

const DAY = new Intl.DateTimeFormat(undefined, {
  weekday: "short",
  day: "numeric",
  month: "short",
});

/**
 * One flat array of headers and entries — FlashList wants a single list, not
 * SectionList's nested shape. Assumes `entries` is already newest-first.
 *
 * `now` is injectable so "TODAY"/"YESTERDAY" labels are testable.
 */
export function toRows(
  entries: Entry[],
  now: number = Date.now(),
): TimelineRow[] {
  const rows: TimelineRow[] = [];
  let currentDay = "";

  for (const entry of entries) {
    const day = dayKey(entry.createdAt);
    if (day !== currentDay) {
      currentDay = day;
      rows.push({
        kind: "header",
        key: `day:${day}`,
        label: labelFor(entry.createdAt, now),
      });
    }
    rows.push({ kind: "entry", key: entry.id, entry });
  }

  return rows;
}

/** Indices of the header rows — exactly what `stickyHeaderIndices` wants. */
export function headerIndices(rows: TimelineRow[]) {
  return rows.flatMap((row, index) => (row.kind === "header" ? [index] : []));
}

function labelFor(date: Date, now: number) {
  const day = dayKey(date);
  const today = dayKey(new Date(now));
  const yesterday = dayKey(new Date(now - DAY_MS));

  if (day === today) return `TODAY · ${DAY.format(date)}`;
  if (day === yesterday) return `YESTERDAY · ${DAY.format(date)}`;
  return DAY.format(date).toUpperCase();
}

Swipe-to-delete is two pieces — the timer that owns the undo window, and the gesture wrapper that triggers it. Filter pendingId out of rows and the row vanishes instantly while the DB write waits. The hook takes a commitDelete function rather than a db handle, so it stays agnostic about what "delete" means. In the wrapper, ReanimatedSwipeable reports the direction the row moved: revealing right-hand actions slides it left, so a full swipe is SwipeDirection.LEFT. A committedRef guard stops a button tap during the open animation from committing twice (a duplicate would flush the first delete past its undo window).

import { useCallback, useEffect, useRef, useState } from "react";

/**
 * Optimistic delete: the row disappears from the list immediately, the DB write
 * happens when the undo window closes. Filter `pendingId` out of your list data.
 *
 * Takes the commit function instead of a db handle, so it stays agnostic about
 * what "delete" means (soft delete + outbox, here).
 */
export function useDeleteWithUndo(
  commitDelete: (id: string) => Promise<void>,
  windowMs = 4000,
) {
  const [pendingId, setPendingId] = useState<string | null>(null);
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null);
  const pending = useRef<string | null>(null);
  const commitRef = useRef(commitDelete);

  useEffect(() => {
    commitRef.current = commitDelete;
  }, [commitDelete]);

  const commit = useCallback(async (id: string) => {
    timer.current = null;
    pending.current = null;
    setPendingId(null);
    await commitRef.current(id);
  }, []);

  // Commit whatever is still waiting in the undo window, right now.
  const flushPending = useCallback(() => {
    if (timer.current && pending.current) {
      clearTimeout(timer.current);
      void commitRef.current(pending.current);
    }
  }, []);

  const remove = useCallback(
    (id: string) => {
      // A second swipe commits the first immediately rather than dropping it.
      flushPending();
      pending.current = id;
      setPendingId(id);
      timer.current = setTimeout(() => void commit(id), windowMs);
    },
    [commit, flushPending, windowMs],
  );

  const undo = useCallback(() => {
    if (timer.current) clearTimeout(timer.current);
    timer.current = null;
    pending.current = null;
    setPendingId(null);
  }, []);

  // Leaving the screen must not silently cancel the delete the user asked for.
  // Refs, not state, so this runs once on unmount rather than on every change.
  useEffect(() => flushPending, [flushPending]);

  return { pendingId, remove, undo };
}

Autosave is the other place a beginner reaches for a spinner. Don't: the write is local and takes under a millisecond. Three rescue paths matter: the debounce timer, AppState leaving active, and unmount (swiping the modal closed). A dirty ref keeps flush from writing when nothing changed, because every write becomes an outbox operation.

src/projects/offline-journal/hooks/useAutosave.tsts
import { useCallback, useEffect, useRef, useState } from "react";
import { AppState } from "react-native";

/**
 * Debounced autosave. Returns the last saved time for the quiet "Saved 07:13 ✓"
 * hint — never a spinner, the write is local and instant.
 */
export function useAutosave<T>(
  value: T,
  save: (value: T) => Promise<void>,
  delay = 800,
) {
  const [savedAt, setSavedAt] = useState<Date | null>(null);
  const latest = useRef({ value, save });
  const skipFirst = useRef(true);
  const dirty = useRef(false);

  useEffect(() => {
    latest.current = { value, save };
  }, [value, save]);

  const flush = useCallback(async () => {
    if (!dirty.current) return; // nothing typed since the last save
    dirty.current = false;
    await latest.current.save(latest.current.value);
    setSavedAt(new Date());
  }, []);

  useEffect(() => {
    if (skipFirst.current) {
      skipFirst.current = false; // don't write a draft the user never touched
      return;
    }
    dirty.current = true;
    const timer = setTimeout(() => void flush(), delay);
    return () => clearTimeout(timer);
  }, [value, delay, flush]);

  // The keystroke inside the debounce window must survive an app switch.
  useEffect(() => {
    const subscription = AppState.addEventListener("change", (state) => {
      if (state !== "active") void flush();
    });
    return () => subscription.remove();
  }, [flush]);

  // ...and closing the modal with the swipe gesture instead of "Done".
  useEffect(() => () => void flush(), [flush]);

  return { savedAt, flush };
}

src/projects/offline-journal/db/queries/search.tsts
import type { SQLiteDatabase } from "expo-sqlite";

import type { Mood, SearchHit } from "../../models/Entry";
import { MATCH_END, MATCH_START } from "../../utils/text";

/**
 * FTS5 MATCH takes a query *language*, not a plain string — a stray quote or a
 * bare `-` is a syntax error. Quote every term and append `*` for prefix search.
 */
export function toMatchQuery(input: string) {
  return input
    .trim()
    .split(/\s+/)
    .filter(Boolean)
    .map((word) => `"${word.replace(/"/g, '""')}"*`)
    .join(" ");
}

export type SearchFilters = {
  text: string;
  mood?: Mood | null;
  tag?: string | null;
  limit?: number;
};

type HitRow = {
  id: string;
  created_at: number;
  title: string;
  excerpt: string;
  mood: Mood | null;
};

const toHit = (row: HitRow): SearchHit => ({
  id: row.id,
  createdAt: new Date(row.created_at),
  title: row.title,
  excerpt: row.excerpt,
  mood: row.mood,
});

/** Extra WHERE clauses shared by the FTS and the filter-only paths. */
function filterClauses({ mood, tag }: SearchFilters) {
  const clauses: string[] = [];
  const params: (string | number)[] = [];
  if (mood) {
    clauses.push("AND e.mood = ?");
    params.push(mood);
  }
  if (tag) {
    clauses.push(`AND EXISTS (
      SELECT 1 FROM entry_tags et JOIN tags t ON t.id = et.tag_id
      WHERE et.entry_id = e.id AND t.name = ?)`);
    params.push(tag);
  }
  return { sql: clauses.join("\n"), params };
}

/**
 * Text goes through FTS5 and is ranked by bm25; with no text but a filter set,
 * it degrades to a plain filtered listing. No text and no filter: no results
 * (the screen shows its "type to search" empty state).
 */
export async function searchEntries(
  db: SQLiteDatabase,
  filters: SearchFilters,
): Promise<SearchHit[]> {
  const limit = filters.limit ?? 50;
  const match = toMatchQuery(filters.text);
  const extra = filterClauses(filters);

  if (!match) {
    if (!filters.mood && !filters.tag) return [];
    const rows = await db.getAllAsync<HitRow>(
      `SELECT e.id, e.created_at, e.title, e.mood,
              substr(e.body, 1, 120) AS excerpt
       FROM entries e
       WHERE e.deleted_at IS NULL
       ${extra.sql}
       ORDER BY e.created_at DESC
       LIMIT ?`,
      [...extra.params, limit],
    );
    return rows.map(toHit);
  }

  const rows = await db.getAllAsync<HitRow>(
    `SELECT e.id,
            e.created_at,
            e.title,
            e.mood,
            snippet(entries_fts, 1, ?, ?, '…', 12) AS excerpt
     FROM entries_fts f
     JOIN entries e ON e.rowid = f.rowid
     WHERE entries_fts MATCH ?
       AND e.deleted_at IS NULL
     ${extra.sql}
     ORDER BY bm25(entries_fts, 2.0, 1.0)   -- title weighted 2x over body
     LIMIT ?`,
    [MATCH_START, MATCH_END, match, ...extra.params, limit],
  );
  return rows.map(toHit);
}

/** The comparison to run once, then never use again. */
export async function searchEntriesSlowly(
  db: SQLiteDatabase,
  input: string,
  limit = 50,
) {
  return db.getAllAsync<HitRow>(
    `SELECT id, created_at, title, mood, substr(body, 1, 120) AS excerpt
     FROM entries
     WHERE deleted_at IS NULL AND (title LIKE ? OR body LIKE ?)
     ORDER BY created_at DESC
     LIMIT ?`,
    `%${input}%`,
    `%${input}%`,
    limit,
  );
}

/**
 * Times both paths over the same data. FTS stays flat as the table grows;
 * LIKE '%x%' is a full scan per keystroke. Run it over a few thousand seeded
 * entries and write the two numbers down.
 */
export async function benchmarkSearch(
  db: SQLiteDatabase,
  input: string,
  runs = 5,
) {
  const time = async (fn: () => Promise<unknown>) => {
    const start = performance.now();
    for (let i = 0; i < runs; i++) await fn();
    return (performance.now() - start) / runs;
  };

  const ftsMs = await time(() => searchEntries(db, { text: input }));
  const likeMs = await time(() => searchEntriesSlowly(db, input));
  const rows = await db.getFirstAsync<{ n: number }>(
    "SELECT COUNT(*) AS n FROM entries",
  );
  return { ftsMs, likeMs, rows: rows?.n ?? 0 };
}

 * Debounced, live search. The select is memoised on the DEBOUNCED text, so the
 * query re-runs at most every 250 ms — not on every keystroke — and still
 * refreshes when an entry changes underneath the results.
 */
export function useSearch(text: string, mood: Mood | null, tag: string | null) {
  const query = useDebouncedValue(text, 250);
  const select = useCallback(
    (db: SQLiteDatabase) => searchEntries(db, { text: query, mood, tag }),
    [query, mood, tag],
  );
  const result = useLiveQuery(TABLES, select, NO_HITS);
  return { ...result, query, settled: query === text };
}

  if (!directory.exists) directory.create({ intermediates: true });
  return directory;

 * iOS changes the absolute container path on app updates, so an absolute URI in
 * SQLite is a bug that only shows up after your next release.

export function resolveAttachmentUri(relative: string) {
  return new File(Paths.document, relative).uri;

export type AttachSource = "library" | "camera";

async function pick(source: AttachSource) {
  if (source === "camera") {
    const permission = await ImagePicker.requestCameraPermissionsAsync();
    if (!permission.granted) return null;
    return ImagePicker.launchCameraAsync({
      mediaTypes: ["images"],
      quality: 0.9,

/**
 * Pick -> downscale -> thumbnail -> blurhash -> copy into documents -> row.
 * Returns the new attachment id, or null if the user cancelled.
 */
export async function attachImage(
  db: SQLiteDatabase,
  entryId: string,
  source: AttachSource = "library",
) {
  const picked = await pick(source);
  if (!picked || picked.canceled) return null;
  const asset = picked.assets[0];

  // Downscale first: a 12 MP original in a list row is pure waste. Never upscale.
  const main = ImageManipulator.manipulate(asset.uri);
  if (asset.width > MAX_EDGE) main.resize({ width: MAX_EDGE });
  const saved = await (
    await main.renderAsync()
  ).saveAsync({ format: SaveFormat.JPEG, compress: 0.8 });

  const thumb = await (
    await ImageManipulator.manipulate(saved.uri)
      .resize({ width: THUMB_EDGE })
      .renderAsync()
  ).saveAsync({ format: SaveFormat.JPEG, compress: 0.7 });

  // Blurhash is a nicety — a failure here must not lose the photo.
  const blurhash = await Image.generateBlurhashAsync(thumb.uri, [4, 3]).catch(
    () => null,
  );

  // The picker and the manipulator both hand back cache URIs. Copy into
  // documents or the file vanishes the next time the OS needs space.
  const id = ulid();
  const filePath = `${ROOT}/${id}.jpg`;
  const thumbPath = `${THUMBS}/${id}.jpg`;
  const target = new File(dir(ROOT), `${id}.jpg`);
  const thumbTarget = new File(dir(THUMBS), `${id}.jpg`);
  await new File(saved.uri).copy(target);
  await new File(thumb.uri).copy(thumbTarget);

  await insertAttachment(db, {
    id,
    entryId,
    file_uri: filePath,
    thumb_uri: thumbPath,
    blurhash,
    mime: "image/jpeg",
    width: saved.width,
    height: saved.height,
    bytes: target.size ?? 0,
  });

  return id;
}

/**
 * Deletes every file in the attachments tree that no row references. Run after
 * purges and from Settings; it is the safety net for every crash between "row
 * deleted" and "file deleted".
 */
export async function sweepOrphans(db: SQLiteDatabase) {
  const known = await referencedPaths(db);
  let removed = 0;

  for (const relative of [ROOT, THUMBS]) {
    const directory = new Directory(Paths.document, relative);
    if (!directory.exists) continue;
    for (const item of directory.list()) {
      if (item instanceof File && !known.has(`${relative}/${item.name}`)) {
        item.delete();
        removed++;
      }
    }
  }
  return removed;
}
Two URIs, two lifetimes

The picker and the manipulator both return cache URIs. Store one in SQLite and your attachment works perfectly until the OS reclaims space — then the row points at nothing, days later, on someone else's device. Copy into Paths.document before you insert the row, and store the path relative to it: iOS changes the absolute container path across app updates, so an absolute URI in SQLite is a bug that only appears after your next release. M6 Sync engine

Goal: the outbox drains reliably and exactly once.
  • Outbox table + transactional writes, with compaction of never-attempted rows.
  • Pure policy module first (sync/policy.ts) and its tests; then the engine: pull (since cursor) → merge → push (drain outbox) → update cursor.
  • Validate the pull response, check the network cheaply before spending a backoff step, and read settings via ensureSettingsHydrated() because a headless launch runs before persisted state loads.
  • Trigger on: entering the journal, app foreground, network regained (an edge-triggered expo-network listener), manual button, a 10-second debounced kick after local writes, and a periodic background task.
  • Register a background task with expo-background-task; log every invocation so you can see how rarely iOS actually runs it.
  • Sync status UI: idle / syncing / N pending / error, in Settings and as a subtle timeline banner. Pending and dead counts come from the outbox table; the run phase lives in an in-memory store.

src/projects/offline-journal/sync/policy.tsts
import type { OutboxOp } from "../models/Entry";

/**
 * The sync engine's decisions, as pure functions. None of this touches the
 * database or the network, so every rule is unit-tested in isolation.
 */

/** After this many failed attempts an outbox item is dead-lettered. */
export const MAX_ATTEMPTS = 6;

const BASE_DELAY_MS = 1_000;
const MAX_DELAY_MS = 300_000;

/**
 * Exponential backoff with jitter, capped at five minutes. The jitter matters
 * more than it looks: without it every device that went offline together
 * retries together, in lockstep, forever.
 */
export function backoffDelay(
  attempts: number,
  random: () => number = Math.random,
) {
  const exponential = Math.min(2 ** attempts * BASE_DELAY_MS, MAX_DELAY_MS);
  return exponential + Math.floor(random() * 1000);
}

export type ResponseClass = "ok" | "retry" | "dead";

/**
 * 2xx: done. 5xx, 408 (timeout) and 429 (rate limit): transient, back off.
 * Every other 4xx: the server will never accept this payload — dead-letter it
 * and surface it instead of retrying a request that cannot succeed.
 */
export function classifyStatus(status: number): ResponseClass {
  if (status >= 200 && status < 300) return "ok";
  if (status === 408 || status === 429) return "retry";
  if (status >= 400 && status < 500) return "dead";
  return "retry";
}

/**
 * Outbox compaction. Autosave writes every ~800 ms, and shipping each keystroke
 * as its own request is waste — so a new op folds into the not-yet-sent item
 * for the same entity. The rule is "what does the server need to end up
 * correct?":
 *   create + update -> create (server never saw it; send the latest body)
 *   update + update -> update
 *   any    + delete -> delete
 *   delete + create/update -> the new op (an undo that re-saved the row)
 */
export function mergeOutboxOp(previous: OutboxOp, next: OutboxOp): OutboxOp {
  if (next === "delete") return "delete";
  if (previous === "create") return "create";
  return next;
}

export type RemoteEntry = {
  id: string;
  title: string;
  body: string;
  mood: number | null;
  created_at: number;
  updated_at: number;
  deleted_at: number | null;
  tags?: string[];
};

export type PullResponse = { entries: RemoteEntry[]; serverTime: number };

const isNumberOrNull = (value: unknown) =>
  value === null || typeof value === "number";

/**
 * Never trust the wire. A malformed row is dropped rather than written; one bad
 * record must not poison the whole pull or the local database.
 */
export function parsePullResponse(json: unknown): PullResponse {
  if (typeof json !== "object" || json === null)
    throw new Error("pull: response is not an object");

  const { entries, serverTime } = json as Record<string, unknown>;
  if (typeof serverTime !== "number")
    throw new Error("pull: missing serverTime");
  if (!Array.isArray(entries)) throw new Error("pull: missing entries");

  const valid = entries.filter((raw): raw is RemoteEntry => {
    if (typeof raw !== "object" || raw === null) return false;
    const row = raw as Record<string, unknown>;
    return (
      typeof row.id === "string" &&
      typeof row.title === "string" &&
      typeof row.body === "string" &&
      isNumberOrNull(row.mood) &&
      typeof row.created_at === "number" &&
      typeof row.updated_at === "number" &&
      isNumberOrNull(row.deleted_at ?? null) &&
      (row.tags === undefined ||
        (Array.isArray(row.tags) &&
          row.tags.every((tag) => typeof tag === "string")))
    );
  });

  return {
    entries: valid.map((row) => ({
      ...row,
      deleted_at: row.deleted_at ?? null,
    })),
    serverTime,
  };
}

/** Clamp a remote mood into the 1..5 range the schema expects. */
export function sanitizeMood(mood: number | null): 1 | 2 | 3 | 4 | 5 | null {
  if (mood === null || !Number.isInteger(mood) || mood < 1 || mood > 5)
    return null;
  return mood as 1 | 2 | 3 | 4 | 5;
}

export type HttpResponse = {

  ok: boolean;

const TIMEOUT_MS = 10_000;

const sleep = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));

/**
 * A ~30-line fetch client instead of the shared axios instance: the sync engine
 * needs the raw status code for every response (axios throws on non-2xx) and a
 * per-call base URL the user can change in Settings.
 *
 * `latencyMs` and `failureRate` are the fault-injection knobs from Settings —
 * they let you drive the 5xx/backoff paths on demand.
 */
export async function request(
  settings: SyncSettings,
  path: string,
  init: {
    method?: string;
    body?: string;
    headers?: Record<string, string>;
  } = {},
): Promise<HttpResponse> {
  if (settings.latencyMs > 0) await sleep(settings.latencyMs);
  if (settings.failureRate > 0 && Math.random() < settings.failureRate) {
    return { status: 503, ok: false, json: async () => ({ injected: true }) };
  }

  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), TIMEOUT_MS);
  try {
    const response = await fetch(
      `${settings.baseUrl.replace(/\/+$/, "")}${path}`,
      {
        method: init.method ?? "GET",
        body: init.body,
        headers: { accept: "application/json", ...init.headers },
        signal: controller.signal,
      },
    );
    return {
      status: response.status,
      ok: response.ok,
      json: () => response.json() as Promise<unknown>,
    };
  } finally {
    clearTimeout(timer);
  }
}

/**
 * Server contract (any mock that honours it works — json-server, a Worker…):
 *
 *   GET    /entries?since=<cursor>  -> { entries: RemoteEntry[], serverTime }
 *   PUT    /entries/:id             upsert on the client ULID; body = payload
 *   DELETE /entries/:id             idempotent tombstone
 *
 * Conflict rule, stated explicitly: last-write-wins by `updated_at`, and a row
 * with unsent local edits (dirty = 1) is never overwritten by a pull. The
 * client ULID is the idempotency key, so replaying any request is harmless.
 */

const CURSOR_KEY = "last_pulled_at";
export const LAST_SYNCED_KEY = "last_synced_at";
export const LAST_ERROR_KEY = "last_error";

export type { SyncResult };

let inFlight: Promise<SyncResult> | null = null;
let again = false;
let localWriteTimer: ReturnType<typeof setTimeout> | null = null;

/** How long local writes are coalesced before they trigger a sync. */
const LOCAL_WRITE_DELAY_MS = 10_000;

/**
 * Run-lock. Foreground, network-regained, manual button, local writes and the
 * background task all call this; without the lock two runs push the same outbox
 * row twice. A kick that lands mid-run schedules exactly one follow-up run, so
 * an edit made during a sync is not left waiting for the next trigger.
 */
export function kick(): Promise<SyncResult> {
  // Any run ships the outbox, so a pending local-write kick is now redundant.
  if (localWriteTimer) {
    clearTimeout(localWriteTimer);
    localWriteTimer = null;
  }
  if (inFlight) {
    again = true;
    return inFlight;
  }
  inFlight = run().finally(() => {
    inFlight = null;
    if (again) {
      again = false;
      void kick();
    }
  });
  return inFlight;
}

/**
 * Trailing debounce for kicks caused by local writes. Autosave writes every
 * typing pause; syncing each one would be a full pull + push per pause. The
 * outbox already holds every change durably, so waiting costs nothing. Manual
 * and lifecycle triggers keep calling `kick()` and run immediately.
 */
export function kickSoon() {
  if (localWriteTimer) clearTimeout(localWriteTimer);
  localWriteTimer = setTimeout(() => {
    localWriteTimer = null;
    void kick();
  }, LOCAL_WRITE_DELAY_MS);
}

async function run(): Promise<SyncResult> {
  const { sync } = await ensureSettingsHydrated();
  if (!sync.enabled || !sync.baseUrl) {
    return finish({ pulled: 0, pushed: 0, failed: 0, skipped: "disabled" });
  }

  // Cheap pre-check: don't burn a backoff step on every item when we already
  // know there is no route. `false` only — `undefined` means "unknown", so try.
  const network = await Network.getNetworkStateAsync().catch(() => null);
  if (
    network?.isInternetReachable === false ||
    network?.isConnected === false
  ) {
    return finish({ pulled: 0, pushed: 0, failed: 0, skipped: "offline" });
  }

  // The background task can wake the app headless, before any screen (and so
  // before SQLiteProvider's onInit) has run. getDb() opens and migrates once.
  const db = await getDb();

  useSyncStore.getState().setPhase("syncing");
  try {
    const pulled = await pull(db, sync); // remote first, so unsent local edits win
    const { pushed, failed } = await push(db, sync);
    await setMeta(db, LAST_SYNCED_KEY, String(Date.now()));
    await deleteMeta(db, LAST_ERROR_KEY);
    return finish({ pulled, pushed, failed });
  } catch (cause) {
    const error = cause instanceof Error ? cause.message : String(cause);
    await setMeta(db, LAST_ERROR_KEY, error).catch(() => undefined);
    // Offline is not an emergency: the outbox still holds every change.
    return finish({ pulled: 0, pushed: 0, failed: 0, error });
  }
}

function finish(result: SyncResult) {
  useSyncStore.getState().finish(result);
  return result;
}

async function pull(db: SQLiteDatabase, settings: SyncSettings) {
  const cursor = (await getMeta(db, CURSOR_KEY)) ?? "0";
  const response = await request(
    settings,
    `/entries?since=${encodeURIComponent(cursor)}`,
  );
  if (!response.ok) throw new Error(`pull failed: HTTP ${response.status}`);

  const { entries, serverTime } = parsePullResponse(await response.json());

  await db.withTransactionAsync(async () => {
    for (const remote of entries) {
      // Last-write-wins by updated_at, and never clobber a row with unsent local
      // edits — that WHERE clause is the entire conflict policy.
      const result = await db.runAsync(
        `INSERT INTO entries (id, title, body, mood, created_at, updated_at, deleted_at, remote_id, dirty)
         VALUES (?, ?, ?, ?, ?, ?, ?, ?, 0)
         ON CONFLICT (id) DO UPDATE SET
           title      = excluded.title,
           body       = excluded.body,
           mood       = excluded.mood,
           updated_at = excluded.updated_at,
           deleted_at = excluded.deleted_at,
           remote_id  = excluded.remote_id
         WHERE entries.dirty = 0 AND entries.updated_at < excluded.updated_at`,
        remote.id,
        remote.title,
        remote.body,
        sanitizeMood(remote.mood),
        remote.created_at,
        remote.updated_at,
        remote.deleted_at,
        remote.id,
      );
      // `changes` is 0 when the WHERE above rejected the update, so tags only
      // follow a remote row that actually won.
      if (result.changes > 0 && remote.tags) {
        await writeTags(db, remote.id, remote.tags);
      }
    }
    await setMeta(db, CURSOR_KEY, String(serverTime));
  });

  return entries.length;
}

async function push(db: SQLiteDatabase, settings: SyncSettings) {
  const batch = await claimBatch(db, 25);
  let pushed = 0;
  let failed = 0;

  for (const item of batch) {
    try {
      // PUT on the client-generated ULID: replaying it is a no-op, so a lost
      // response costs nothing. That is what makes retries safe.
      const response = await request(
        settings,
        `/entries/${encodeURIComponent(item.entity_id)}`,
        {
          method: item.op === "delete" ? "DELETE" : "PUT",
          headers: {
            "content-type": "application/json",
            "idempotency-key": `${item.entity_id}:${item.id}`,
          },
          body: item.op === "delete" ? undefined : item.payload,
        },
      );

      const verdict = classifyStatus(response.status);
      if (verdict === "ok") {
        await markDone(db, item);
        pushed++;
      } else if (verdict === "dead") {
        // The server will never accept this. Dead-letter it and surface it.
        await failItem(db, item, `HTTP ${response.status}`, {
          permanent: true,
        });
        failed++;
      } else {
        await failItem(db, item, `HTTP ${response.status}`); // retry with backoff
        failed++;
      }
    } catch (cause) {
      await failItem(db, item, String(cause)); // offline: stay queued, no drama
      failed++;
    }
  }

  return { pushed, failed };
}

async function markDone(db: SQLiteDatabase, item: OutboxItem) {
  await db.withTransactionAsync(async () => {
    await completeItem(db, item);
    // Only clear `dirty` if no newer edit is still queued for this row.
    await db.runAsync(
      `UPDATE entries SET dirty = 0, remote_id = COALESCE(remote_id, id)
       WHERE id = ? AND NOT EXISTS (SELECT 1 FROM outbox WHERE entity_id = ?)`,
      item.entity_id,
      item.entity_id,
    );
  });
}

/**
 * The automatic triggers. Mounted ONCE, in the project layout — putting these
 * in every screen that shows status would multiply the listeners.
 */
export function useSyncTriggers() {
  const enabled = useSettingsStore((state) => state.sync.enabled);

  useEffect(() => {
    if (!enabled) {
      void unregisterSyncTask();
      return;
    }

    // Trigger 0: entering the journal / turning sync on.
    void kick();
    // Trigger 4: the periodic background task (a hint, not a schedule).
    void registerSyncTask();

    // Trigger 1: coming back to the foreground.
    const appState = AppState.addEventListener("change", (next) => {
      if (next === "active") void kick();
    });

    // Trigger 2: the network coming back. Edge-triggered: only on the
    // transition to reachable, not on every state event.
    let reachable: boolean | undefined;
    const network = addNetworkStateListener((state) => {
      const now = state.isInternetReachable ?? state.isConnected;
      if (now && reachable === false) void kick();
      reachable = now;
    });

    return () => {
      appState.remove();
      network.remove();
    };
  }, [enabled]);
}

M7 Lock, export, polish

Goal: shippable feel.
  • Biometric lock with expo-local-authentication; re-lock when the app goes to background past a threshold (AppState listener). Cover the content as soon as the app goes inactive, whatever the grace period, so the app-switcher snapshot is clean.
  • Gate the lock on settings hydration: before AsyncStorage loads you cannot rule the lock out, so stay covered. If nothing is enrolled, unlock rather than brick the user out of their data.
  • Export to JSON and Markdown; save via expo-sharing.
  • Onboarding flow, gated by a persisted flag and by hydration (otherwise every cold start flashes onboarding).
  • Haptics on save/delete (this repo already has expo-haptics).
  • App icon, splash, and a real name.

import * as LocalAuthentication from "expo-local-authentication";
import { useCallback, useEffect } from "react";
import { AppState } from "react-native";

import { useLockStore } from "../stores/lockStore";
import { useSettingsHydrated, useSettingsStore } from "../stores/settingsStore";

/** Can this device authenticate at all? No enrolled biometrics and no passcode = no. */
export async function canAuthenticate() {
  const [hardware, enrolled, level] = await Promise.all([
    LocalAuthentication.hasHardwareAsync(),
    LocalAuthentication.isEnrolledAsync(),
    LocalAuthentication.getEnrolledLevelAsync(),
  ]);
  return (
    (hardware && enrolled) || level !== LocalAuthentication.SecurityLevel.NONE
  );
}

export async function promptAuthentication(message: string) {
  const result = await LocalAuthentication.authenticateAsync({
    promptMessage: message,
    fallbackLabel: "Use passcode",
    cancelLabel: "Cancel",
  });
  return result.success;
}

export function useAppLock() {
  const hydrated = useSettingsHydrated();
  const locked = useLockStore((state) => state.locked);
  const obscured = useLockStore((state) => state.obscured);
  const lock = useLockStore((state) => state.lock);
  const unlock = useLockStore((state) => state.unlock);
  const setObscured = useLockStore((state) => state.setObscured);
  const enabled = useSettingsStore((state) => state.biometricLock);
  const graceMs = useSettingsStore((state) => state.lockAfterMs);

  useEffect(() => {
    if (!enabled) return;

    let leftAt: number | null = null;
    const subscription = AppState.addEventListener("change", (state) => {
      if (state === "active") {
        setObscured(false);
        if (leftAt !== null && Date.now() - leftAt >= graceMs) lock();
        leftAt = null;
      } else {
        // "inactive" fires for the app switcher too — that is the moment the
        // OS takes the snapshot, so cover NOW, whatever the grace period says.
        setObscured(true);
        leftAt ??= Date.now();
      }
    });

    return () => subscription.remove();
  }, [enabled, graceMs, lock, setObscured]);

  const authenticate = useCallback(async () => {
    // Before hydration we don't know whether the lock is on. Doing nothing is
    // the safe answer; the gate re-prompts when this callback's identity
    // changes after hydration.
    if (!hydrated) return false;
    if (!enabled) {
      unlock();
      return true;
    }
    if (!(await canAuthenticate())) {
      unlock(); // nothing enrolled: never brick the user out of their data
      return true;
    }
    const success = await promptAuthentication("Unlock your journal");
    if (success) unlock();
    return success;
  }, [enabled, hydrated, unlock]);

  return {
    // Until settings load, cover the content: we can't yet rule the lock out.
    locked: !hydrated || (enabled && locked),
    obscured: enabled && obscured,
    authenticate,
    lockNow: lock,
  };
}

  locked,
  obscured = false,
  onUnlock,
  children,
}: LockGateProps) {
  useEffect(() => {
    // Prompt as soon as we lock — but not while backgrounded, where the system
    // prompt would fail or appear over another app.
    if (locked && !obscured) void onUnlock();
  }, [locked, obscured, onUnlock]);

  const covered = locked || obscured;

  return (
    <View style={styles.fill}>
      {/* Hidden from accessibility while covered, so VoiceOver can't read through. */}
      <View
        style={styles.fill}
        importantForAccessibility={covered ? "no-hide-descendants" : "auto"}
        accessibilityElementsHidden={covered}
      >
        {children}
      </View>
      {covered ? (
        <View style={StyleSheet.absoluteFill}>
          <LockScreenView onUnlock={locked ? () => void onUnlock() : null} />
        </View>
      ) : null}
    </View>
  );
}

  patchSync: (partial: Partial<SyncSettings>) => void;
};

export const DEFAULT_SYNC: SyncSettings = {
  enabled: false,
  // From app.config.ts `extra.journalSyncUrl`; the user can override it in Settings.
  baseUrl: env.journalSyncUrl,
  latencyMs: 0,
  failureRate: 0,

export const useSettingsStore = create<SettingsState>()(
  persist(
    (set) => ({
      theme: "system",
      fontSize: "medium",
      biometricLock: false,
      lockAfterMs: 0,
      reminder: { enabled: false, hour: 21, minute: 0 },
      sync: DEFAULT_SYNC,
      onboarded: false,
      patch: (partial) => set(partial),
      patchSync: (partial) =>
        set((state) => ({ sync: { ...state.sync, ...partial } })),
    }),
    {
      name: "journal-settings",
      storage: createJSONStorage(() => AsyncStorage),
      version: 1,
      // Functions are not state; never write them to disk.
      partialize: ({ patch, patchSync, ...settings }) => settings,
      // Shallow merge would drop new nested keys added in a later release.
      merge: (persisted, current) => {
        const saved = (persisted ?? {}) as Partial<Settings>;
        return {
          ...current,
          ...saved,
          reminder: { ...current.reminder, ...saved.reminder },
          sync: { ...current.sync, ...saved.sync },
        };
      },
    },
  ),
);

// AsyncStorage is async, so the first render sees the defaults. Gate anything
// that depends on persisted values (the onboarding redirect, the app lock) on
// hydration, or every cold start flashes the wrong thing. useSyncExternalStore
// rather than useState + effect: no missed event between render and subscribe.
const subscribeHydration = (onChange: () => void) =>
  useSettingsStore.persist.onFinishHydration(onChange);
const getHydrated = () => useSettingsStore.persist.hasHydrated();

export function useSettingsHydrated() {
  return useSyncExternalStore(subscribeHydration, getHydrated, getHydrated);
}

/**
 * For non-React callers (the headless background task): make sure persisted
 * settings are loaded before reading them with `getState()`.
 */
export async function ensureSettingsHydrated() {
  if (!useSettingsStore.persist.hasHydrated())
    await useSettingsStore.persist.rehydrate();
  return useSettingsStore.getState();
}

import { File, Paths } from "expo-file-system";
import * as Sharing from "expo-sharing";
import type { SQLiteDatabase } from "expo-sqlite";

import { listEntries } from "../db/queries/entries";
import { toJson, toMarkdownDocument } from "./exportFormat";

export type ExportFormat = "json" | "md";

export async function exportEntries(db: SQLiteDatabase, format: ExportFormat) {
  const entries = await listEntries(db, { limit: 100_000 });
  const stamp = new Date().toISOString().slice(0, 10);

  // Cache, not documents: an export is disposable once it has been shared.
  const file = new File(Paths.cache, `journal-${stamp}.${format}`);
  if (file.exists) file.delete();
  file.create();
  file.write(format === "json" ? toJson(entries) : toMarkdownDocument(entries));

  if (await Sharing.isAvailableAsync()) {
    await Sharing.shareAsync(file.uri, {
      mimeType: format === "json" ? "application/json" : "text/markdown",
      dialogTitle: "Export journal",
      UTI: format === "json" ? "public.json" : "net.daringfireball.markdown",
    });
  }

  return { uri: file.uri, count: entries.length };
}

Failure modes to experience deliberately

Each item says how to provoke the failure, how it shows up, and what the finished code does about it.

  1. Migration that drops data. Provoke: write a bad v2 migration (a table recreate without a backfill) and run it against real data. Shows up: entries vanish, or old entries are unsearchable. Handled by: one transaction per step with the user_version bump inside it, an explicit FTS backfill, and ADD COLUMN for V3. Shipped migrations are never edited; V4 replaces the V2 trigger as a new step.
  2. FTS drift. Provoke: update a row without the trigger in place. Shows up: search returns stale text. Handled by: three triggers (narrowed to UPDATE OF title, body in V4) and rebuildSearchIndex() as the repair, exposed in Settings.
  3. Duplicate sync. Provoke: kick the sync engine twice concurrently with no mutex. Shows up: the server gets two copies. Handled by: the inFlight run-lock plus one queued follow-up, and an idempotency key on every request.
  4. Edit lost in flight. Provoke: type while a PUT is in flight and delete the outbox row by id alone. Shows up: the newer edit never reaches the server. Handled by: completeItem deleting only if the payload is unchanged, and markDone clearing dirty only when nothing is queued.
  5. Pull clobbers local edits. Provoke: remove entries.dirty = 0 from the upsert. Shows up: an unsent edit reverts after a sync. Handled by: the WHERE clause plus pull-before-push.
  6. Background task that never fires. Provoke: register on iOS, wait a day. Shows up: it fired zero or once. Handled by: treating it as a hint (every other trigger works without it), logging each invocation, and defining it at module scope from the root layout.
  7. Headless run reads default settings. Provoke: read getState() in the task. Shows up: logs say "disabled" while Settings says sync is on. Handled by: ensureSettingsHydrated() and the lazy, memoized getDb().
  8. Notification permission denied. Provoke: deny it, then try to schedule. Handled by: getPermissionState() returning "blocked" and an "open Settings" path via Linking.
  9. Cold-start tap lost. Provoke: register the listener in the journal layout and tap a reminder on a killed app. Shows up: you land on the launcher. Handled by: starting the router from the root, reading and clearing the last response, and de-duplicating.
  10. Blocked JS thread. Provoke: run a large synchronous query during a scroll. Handled by: async queries, paging by limit, and coalescing change events behind a 50 ms timer.
  11. App switcher leak and unprotected cold start. Provoke: lock the app but forget to cover on inactive, or unlock before settings hydrate. Shows up: entries readable in the switcher or on first launch. Handled by: the obscured flag and treating "not hydrated" as locked.
  12. Hydration flash. Provoke: remove the hydrated && check before the onboarding redirect. Shows up: every cold start flashes onboarding. Handled by: useSettingsHydrated() built on useSyncExternalStore.

The design choice that makes this possible is to put every side effect behind a seam:

  • Pure helpers take their clock and randomness as parameters: ulid(now, randomBytes), backoffDelay(attempts, random), toRows(entries, now).
  • sync/policy.ts holds every sync decision with no I/O; utils/exportFormat.ts is separate from the file and share-sheet code in utils/export.ts.
  • Every query takes the db handle as its first argument. testing/nodeDatabase.ts is an expo-sqlite-shaped adapter over Node's built-in node:sqlite, so migrations, FTS5 triggers, outbox queries and the conflict rule run against a real SQLite engine in memory.
  • syncEngine.test.ts mocks only the edges (getDb, request, expo-network, the settings store) and drives the real kick(). Assert on database state and requests sent, not on the mocks.

Unit tests live in src/projects/offline-journal/__tests__/, never under src/app/ (that would create routes). TypeScript 6 does not auto-load @types/*, so tsconfig.json sets "types": ["jest"].
