01 · Offline-First Journal

A private, encrypted-at-rest journaling app that is fully functional with the network permanently off — and reconciles correctly when it comes back.

Foundation tier Runs in Expo Go ~2 weeks Core skill: local-first data
Why this one first

Almost every RN tutorial starts by fetching from an API, which teaches you to treat the network as the source of truth. That habit produces apps that spin forever in a tunnel. Starting local-first inverts the model: the device is the source of truth, and the server is a replica you reconcile with. Everything else in this path is easier once you think that way.

How to read the code on this page

Every snippet is a whole file — real paths, real imports, written against Expo SDK 57 / RN 0.86 and the repo's own conventions (@/src/… aliases, double quotes, ThemedText/ThemedView from src/shared/). They use plain expo-sqlite, which is the module this repo already ships; the Drizzle variant is shown once, as an optional path.

Read them as reference, not as a repo to clone. Most of the paths in the filename headers don't exist yet — they are the files this project has you write; the ones under src/shared/ already do. Type each snippet out, and when something looks arbitrary — the WHERE entries.dirty = 0 in the pull merge, the next_attempt_at column, the module-scope defineTask — that is the part worth stopping on. Those lines are the entire lesson of this project.

UI design & screens

Design language

  • Tone: calm, paper-like, content-forward. Generous whitespace, one accent colour, serif for entry body text and sans for chrome.
  • Density: the timeline is the app. Everything else is a modal or a sheet over it.

Interaction details worth building properly

  • Autosave: debounce ~800 ms, write to the drafts row, show a quiet "Saved HH:MM ✓". Never a spinner.
  • Swipe to delete on a timeline row, using Gesture Handler's swipeable — with an undo snackbar rather than a confirm dialog.
  • Sticky day headers in FlashList, driven by section data rather than a separate SectionList.
  • Optimistic delete: the row animates out immediately; the DB delete happens after the undo window expires.
  • Keyboard handling: the compose toolbar must sit on the keyboard, not behind it. Use KeyboardAvoidingView plus react-native-keyboard-controller if you want it smooth.
  • Empty states: first launch, no search results, and a filtered day with nothing in it are three different empty states with three different messages.

What is not in this list

No components/ui/ for generic primitives — themed-text, themed-view, icon-symbol and content-unavailable-view already live in src/shared/components/. Import them; don't re-make them. Conversely, EntryCard and MoodPicker are journal-specific and stay in the slice no matter how reusable they look. Promote to shared/ only when a second project needs the thing.

db/, sync/ and reminders/ aren't in the standard slice subfolder list, and that's fine — the list is a floor, not a cage. A project adds the folders its domain needs; what it must not do is scatter them outside the slice.

Layer rules

  • db/queries/* are pure functions of the db handle. No React, no stores. This makes them unit-testable without a renderer.
  • hooks/* are the only place that binds queries to React (via a live-query hook or TanStack Query with a local query function).
  • Components never import a store or a db module. Props and callbacks only — same discipline you apply to SwiftUI subviews.
  • The sync task is defined at module scope, imported from the project layout. If you define it inside a component it will never run in the background.
  • Nothing in this slice imports from src/projects/store/, and nothing there imports from here. The journal has its own query keys, its own models, its own stores.
  • Every non-route file lives under src/projects/offline-journal/. LockGate is a component, not a destination — parking it under src/app/ would create a real /projects/offline-journal/LockGate route.

src/projects/offline-journal/db/migrations.tsts
import type { SQLiteDatabase } from "expo-sqlite";

export const SCHEMA_VERSION = 2;

const V1 = `
CREATE TABLE entries (
  id          TEXT    PRIMARY KEY NOT NULL,   -- ULID, generated on device
  title       TEXT    NOT NULL DEFAULT '',
  body        TEXT    NOT NULL DEFAULT '',
  mood        INTEGER,                        -- 1..5, null = not set
  created_at  INTEGER NOT NULL,               -- epoch ms
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,                        -- soft delete; hard deletes break sync
  remote_id   TEXT,
  dirty       INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_entries_timeline ON entries (created_at DESC) WHERE deleted_at IS NULL;
CREATE INDEX idx_entries_dirty    ON entries (dirty) WHERE dirty = 1;

CREATE TABLE tags (
  id   TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL UNIQUE
);

CREATE TABLE entry_tags (
  entry_id TEXT NOT NULL REFERENCES entries (id) ON DELETE CASCADE,
  tag_id   TEXT NOT NULL REFERENCES tags (id)    ON DELETE CASCADE,
  PRIMARY KEY (entry_id, tag_id)
);

CREATE TABLE attachments (
  id       TEXT    PRIMARY KEY NOT NULL,
  entry_id TEXT    NOT NULL REFERENCES entries (id) ON DELETE CASCADE,
  file_uri TEXT    NOT NULL,                  -- the blob lives on disk, not here
  mime     TEXT    NOT NULL,
  width    INTEGER,
  height   INTEGER,
  bytes    INTEGER
);
CREATE INDEX idx_attachments_entry ON attachments (entry_id);

CREATE TABLE outbox (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,   -- FIFO by insertion
  op              TEXT    NOT NULL,                    -- create | update | delete
  entity          TEXT    NOT NULL,
  entity_id       TEXT    NOT NULL,
  payload         TEXT    NOT NULL,                    -- JSON
  attempts        INTEGER NOT NULL DEFAULT 0,
  next_attempt_at INTEGER NOT NULL DEFAULT 0,          -- backoff gate
  last_error      TEXT,
  created_at      INTEGER NOT NULL
);
CREATE INDEX idx_outbox_ready ON outbox (next_attempt_at, id);

CREATE TABLE sync_meta (
  key   TEXT PRIMARY KEY NOT NULL,
  value TEXT
);
`;

const V2 = `
-- External-content FTS5: the index stores no copy of the text, it points at
-- entries.rowid. That is why every write needs a trigger below.
CREATE VIRTUAL TABLE entries_fts USING fts5(
  title, body, content = 'entries', content_rowid = 'rowid'
);

-- Backfill first. Skip this and every pre-existing entry is unsearchable.
INSERT INTO entries_fts (rowid, title, body)
  SELECT rowid, title, body FROM entries;

CREATE TRIGGER entries_ai AFTER INSERT ON entries BEGIN
  INSERT INTO entries_fts (rowid, title, body)
    VALUES (new.rowid, new.title, new.body);
END;

CREATE TRIGGER entries_ad AFTER DELETE ON entries BEGIN
  INSERT INTO entries_fts (entries_fts, rowid, title, body)
    VALUES ('delete', old.rowid, old.title, old.body);
END;

CREATE TRIGGER entries_au AFTER UPDATE ON entries BEGIN
  INSERT INTO entries_fts (entries_fts, rowid, title, body)
    VALUES ('delete', old.rowid, old.title, old.body);
  INSERT INTO entries_fts (rowid, title, body)
    VALUES (new.rowid, new.title, new.body);
END;
`;

const MIGRATIONS: Record<number, string> = { 1: V1, 2: V2 };

export async function migrate(db: SQLiteDatabase) {
  // PRAGMAs go outside the transaction: journal_mode cannot change inside one.
  await db.execAsync("PRAGMA journal_mode = WAL");
  await db.execAsync("PRAGMA foreign_keys = ON");

  const row = await db.getFirstAsync<{ user_version: number }>("PRAGMA user_version");
  let version = row?.user_version ?? 0;

  while (version < SCHEMA_VERSION) {
    const next = version + 1;
    // One transaction per step, and the version bump rides inside it — a crash
    // mid-upgrade leaves you on a version that actually matches the schema.
    await db.withTransactionAsync(async () => {
      await db.execAsync(MIGRATIONS[next]);
      await db.execAsync(`PRAGMA user_version = ${next}`); // cannot be a bound param
    });
    version = next;
  }
}

/** Repair tool for when a trigger was missing or wrong. */
export async function rebuildSearchIndex(db: SQLiteDatabase) {
  await db.execAsync("INSERT INTO entries_fts (entries_fts) VALUES ('rebuild')");
}
Three details that bite

PRAGMA journal_mode cannot change inside a transaction, so the PRAGMAs run before the loop. PRAGMA user_version = ? cannot be a bound parameter — it has to be interpolated, which is safe only because the value is a number you control. And the FTS5 table is external content: it stores no copy of the text, so without the three triggers the index silently drifts from the rows.

The two shapes every row travels through — one matching SQLite, one matching the UI. Convert once, in the query layer, and no component ever sees an epoch integer.

   ├─► BEGIN TRANSACTION

The transaction is non-negotiable: the row change and the outbox entry must land together or not at all.

In code, that diagram is one withTransactionAsync call:

src/projects/offline-journal/db/queries/entries.ts · writests
import type { SQLiteDatabase } from "expo-sqlite";

import type { Mood } from "../../models/Entry";
import { ulid } from "../../utils/id";
import { enqueue } from "./outbox";

export type EntryInput = {
  id?: string;
  title: string;
  body: string;
  mood: Mood | null;
};

/**
 * Row change + outbox row in ONE transaction. This is the whole offline-first
 * trick: they land together or not at all, so the queue can never disagree with
 * the data it is supposed to be shipping.
 */
export async function saveEntry(db: SQLiteDatabase, input: EntryInput) {
  const id = input.id ?? ulid();
  const now = Date.now();

  await db.withTransactionAsync(async () => {
    await db.runAsync(
      `INSERT INTO entries (id, title, body, mood, created_at, updated_at, dirty)
       VALUES (?, ?, ?, ?, ?, ?, 1)
       ON CONFLICT (id) DO UPDATE SET
         title      = excluded.title,
         body       = excluded.body,
         mood       = excluded.mood,
         updated_at = excluded.updated_at,
         dirty      = 1`,
      id,
      input.title,
      input.body,
      input.mood,
      now,
      now
    );

    await enqueue(db, input.id ? "update" : "create", id, {
      id,
      title: input.title,
      body: input.body,
      mood: input.mood,
      updated_at: now,
    });
  });

  return id;
}

/** Soft delete. The row stays so the delete can be replayed to the server. */
export async function softDeleteEntry(db: SQLiteDatabase, id: string) {
  const now = Date.now();

  await db.withTransactionAsync(async () => {
    await db.runAsync(
      "UPDATE entries SET deleted_at = ?, updated_at = ?, dirty = 1 WHERE id = ?",
      now,
      now,
      id
    );
    await enqueue(db, "delete", id, { id, deleted_at: now });
  });
}

export async function setTags(db: SQLiteDatabase, entryId: string, names: string[]) {
  await db.withTransactionAsync(async () => {
    for (const name of names) {
      await db.runAsync(
        "INSERT INTO tags (id, name) VALUES (?, ?) ON CONFLICT (name) DO NOTHING",
        ulid(),
        name
      );
    }
    await db.runAsync("DELETE FROM entry_tags WHERE entry_id = ?", entryId);
    for (const name of names) {
      await db.runAsync(
        `INSERT INTO entry_tags (entry_id, tag_id)
         VALUES (?, (SELECT id FROM tags WHERE name = ?))`,
        entryId,
        name
      );
    }
  });
}

And the outbox itself — a table with a backoff column, which is all a retry queue really is:

src/projects/offline-journal/db/queries/outbox.tsts
import type { SQLiteDatabase } from "expo-sqlite";

import type { OutboxItem, OutboxOp } from "../../models/Entry";

export const MAX_ATTEMPTS = 6;

export async function enqueue(
  db: SQLiteDatabase,
  op: OutboxOp,
  entityId: string,
  payload: unknown
) {
  await db.runAsync(
    `INSERT INTO outbox (op, entity, entity_id, payload, created_at)
     VALUES (?, 'entry', ?, ?, ?)`,
    op,
    entityId,
    JSON.stringify(payload),
    Date.now()
  );
}

/** Oldest-first, skipping items still inside their backoff window. */
export async function claimBatch(db: SQLiteDatabase, limit = 25) {
  return db.getAllAsync<OutboxItem>(
    `SELECT id, op, entity, entity_id, payload, attempts
     FROM outbox
     WHERE next_attempt_at <= ? AND attempts < ?
     ORDER BY id
     LIMIT ?`,
    Date.now(),
    MAX_ATTEMPTS,
    limit
  );
}

export async function completeItem(db: SQLiteDatabase, id: number) {
  await db.runAsync("DELETE FROM outbox WHERE id = ?", id);
}

export async function failItem(
  db: SQLiteDatabase,
  item: OutboxItem,
  message: string,
  options: { permanent?: boolean } = {}
) {
  const attempts = options.permanent ? MAX_ATTEMPTS : item.attempts + 1;
  // Exponential backoff with jitter, capped at five minutes.
  const delay = Math.min(2 ** attempts * 1000, 300_000) + Math.floor(Math.random() * 1000);

  await db.runAsync(

Read path

Two viable designs — build the first, then try the second and compare:

  1. Live query. A hook that subscribes to DB change events and re-runs its query. Simplest mental model; you can build it yourself on top of addDatabaseChangeListener, or use Drizzle's live-query helper.
  2. TanStack Query over local reads. Query function reads SQLite, mutations invalidate keys. More boilerplate but a uniform API for local and remote — and it's the same pattern you'll use in Project 03.

Then the live-query hook. addDatabaseChangeListener gives you a table name per changed row; the whole hook is a subscription plus a debounce:

src/projects/offline-journal/hooks/useLiveQuery.tsts
import { addDatabaseChangeListener, useSQLiteContext, type SQLiteDatabase } from "expo-sqlite";
import { useEffect, useState } from "react";

/**
 * Build this before reaching for a library version. Runs `select` once, then
 * re-runs it whenever one of `tables` changes.
 *
 * `select` must be a stable reference (module-level function or useCallback) —
 * a fresh arrow function per render re-subscribes on every render.
 */
export function useLiveQuery<T>(
  tables: readonly string[],
  select: (db: SQLiteDatabase) => Promise<T>,
  initial: T
) {
  const db = useSQLiteContext();
  const [data, setData] = useState<T>(initial);
  const [error, setError] = useState<Error | null>(null);
  const watched = tables.join(",");

  useEffect(() => {
    let cancelled = false;
    let timer: ReturnType<typeof setTimeout> | null = null;

    const load = () => {
      select(db)
        .then((next) => !cancelled && setData(next))
        .catch((cause) => !cancelled && setError(cause as Error));
    };

    load();

    const subscription = addDatabaseChangeListener(({ tableName }) => {
      if (!watched.split(",").includes(tableName)) return;
      // A transaction fires one event per changed row — coalesce the burst.
      if (timer) clearTimeout(timer);
      timer = setTimeout(load, 50);
    });

    return () => {
      cancelled = true;
      if (timer) clearTimeout(timer);
      subscription.remove();
    };
  }, [db, select, watched]);

  return { data, error };
}

Sync semantics to decide (and write down)

  • Conflict rule: last-write-wins by updated_at? Or field-level merge? LWW is fine here — but state it explicitly.
  • Idempotency: the client-generated ULID is the idempotency key. The server must upsert on it.
  • Backoff: exponential with jitter, capped. Cap the attempt count and dead-letter after N.
  • Clock skew: never trust the device clock for ordering across devices. Use a server-assigned version/lamport counter if you go multi-device.
No backend? Good.

import { getRandomBytes } from "expo-crypto";

const ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"; // Crockford base32: no I, L, O, U

/**
 * 26-char ULID: 10 chars of millisecond timestamp + 16 chars of randomness.
 * Sorting by id sorts by creation time, so the timeline can page on the primary
 * key and the id doubles as the sync idempotency key.
 */
export function ulid(now: number = Date.now()): string {
  let time = "";
  let remaining = now;
  for (let i = 0; i < 10; i++) {
    time = ALPHABET[remaining % 32] + time;
    remaining = Math.floor(remaining / 32);
  }

  const bytes = getRandomBytes(16);
  let random = "";
  for (let i = 0; i < 16; i++) random += ALPHABET[bytes[i] % 32]; // 256 % 32 === 0, no bias

  return time + random;
}

import { useSQLiteContext } from "expo-sqlite";
import { useCallback, useEffect, useRef, useState } from "react";

import { softDeleteEntry } from "../db/queries/entries";

/**
 * Optimistic delete: the row disappears from the list immediately, the DB write
 * happens when the undo window closes. Filter `pendingId` out of your list data.
 */
export function useDeleteWithUndo(windowMs = 4000) {
  const db = useSQLiteContext();
  const [pendingId, setPendingId] = useState<string | null>(null);
  const timer = useRef<ReturnType<typeof setTimeout> | null>(null);

  const commit = useCallback(
    async (id: string) => {
      timer.current = null;
      setPendingId(null);
      await softDeleteEntry(db, id);
    },
    [db]
  );

  const remove = useCallback(
    (id: string) => {
      if (timer.current) clearTimeout(timer.current); // a second swipe commits the first
      setPendingId(id);
      timer.current = setTimeout(() => void commit(id), windowMs);
    },
    [commit, windowMs]
  );

  const undo = useCallback(() => {
    if (timer.current) clearTimeout(timer.current);
    timer.current = null;
    setPendingId(null);
  }, []);

  // Leaving the screen must not silently cancel the delete the user asked for.
  useEffect(
    () => () => {
      if (timer.current && pendingId) {
        clearTimeout(timer.current);
        void softDeleteEntry(db, pendingId);
      }
    },
    [db, pendingId]
  );

  return { pendingId, remove, undo };
}

import { useCallback, useEffect, useRef, useState } from "react";
import { AppState } from "react-native";

/**
 * Debounced autosave. Returns the last saved time for the quiet "Saved 07:13 ✓"
 * hint — never a spinner, the write is local and instant.
 */
export function useAutosave<T>(value: T, save: (value: T) => Promise<void>, delay = 800) {
  const [savedAt, setSavedAt] = useState<Date | null>(null);
  const latest = useRef({ value, save });
  const skipFirst = useRef(true);

  useEffect(() => {
    latest.current = { value, save };
  }, [value, save]);

  const flush = useCallback(async () => {
    await latest.current.save(latest.current.value);
    setSavedAt(new Date());
  }, []);

  useEffect(() => {
    if (skipFirst.current) {
      skipFirst.current = false; // don't write a draft the user never touched
      return;
    }
    const timer = setTimeout(() => void flush(), delay);
    return () => clearTimeout(timer);
  }, [value, delay, flush]);

  // The keystroke inside the debounce window must survive an app switch.
  useEffect(() => {
    const subscription = AppState.addEventListener("change", (state) => {
      if (state !== "active") void flush();
    });
    return () => subscription.remove();
  }, [flush]);

  return { savedAt, flush };
}

import type { SQLiteDatabase } from "expo-sqlite";

export type SearchHit = {
  id: string;
  created_at: number;
  title: string;
  excerpt: string;
};

/**
 * FTS5 MATCH takes a query *language*, not a plain string — a stray quote or a
 * bare `-` is a syntax error. Quote every term and append `*` for prefix search.
 */
function toMatchQuery(input: string) {
  return input
    .trim()
    .split(/\s+/)
    .filter(Boolean)
    .map((word) => `"${word.replace(/"/g, '""')}"*`)
    .join(" ");
}

export async function searchEntries(db: SQLiteDatabase, input: string, limit = 50) {
  const match = toMatchQuery(input);
  if (!match) return [];

  return db.getAllAsync<SearchHit>(
    `SELECT e.id,
            e.created_at,
            e.title,
            snippet(entries_fts, 1, '[', ']', '…', 12) AS excerpt
     FROM entries_fts f
     JOIN entries e ON e.rowid = f.rowid
     WHERE entries_fts MATCH ?
       AND e.deleted_at IS NULL
     ORDER BY bm25(entries_fts, 2.0, 1.0)   -- title weighted 2x over body
     LIMIT ?`,
    match,
    limit
  );
}

     ORDER BY created_at DESC
     LIMIT ?`,

}

function attachmentsDir() {
  const dir = new Directory(Paths.document, "attachments");
  if (!dir.exists) dir.create({ intermediates: true });
  return dir;
}

export async function attachImage(db: SQLiteDatabase, entryId: string) {
  const picked = await ImagePicker.launchImageLibraryAsync({
    mediaTypes: ["images"],
    quality: 0.9,
  });
  if (picked.canceled) return null;
  const asset = picked.assets[0];

  // Downscale first: a 12 MP original in a list row is pure waste.
  const context = ImageManipulator.manipulate(asset.uri).resize({ width: 1600 });
  const rendered = await context.renderAsync();
  const saved = await rendered.saveAsync({ format: SaveFormat.JPEG, compress: 0.8 });

  // The picker and the manipulator both hand back cache URIs. Copy into
  // documents or the file vanishes the next time the OS needs space.
  const target = new File(attachmentsDir(), `${ulid()}.jpg`);
  await new File(saved.uri).copy(target);

  await db.runAsync(
    `INSERT INTO attachments (id, entry_id, file_uri, mime, width, height, bytes)
     VALUES (?, ?, ?, 'image/jpeg', ?, ?, ?)`,
    ulid(),
    entryId,
    target.uri,
    saved.width,
    saved.height,
    target.size ?? 0
  );

  return target.uri;
}

/** Delete rows first, files second — then sweep whatever the crash left behind. */
export async function sweepOrphans(db: SQLiteDatabase) {
  const rows = await db.getAllAsync<{ file_uri: string }>("SELECT file_uri FROM attachments");
  const known = new Set(rows.map((row) => row.file_uri));

  let removed = 0;
  for (const item of attachmentsDir().list()) {
    if (item instanceof File && !known.has(item.uri)) {
      item.delete();
      removed++;
    }
  }
  return removed;
}
Two URIs, two lifetimes

The picker and the manipulator both return cache URIs. Store one in SQLite and your attachment works perfectly until the OS reclaims space — then the row points at nothing, days later, on someone else's device. Copy into Paths.document before you insert the row, and never store an absolute URI you did not create.

Goal: the outbox drains reliably and exactly once.

src/projects/offline-journal/sync/syncEngine.tsts
import { db } from "../db/client";
import { claimBatch, completeItem, failItem, getMeta, setMeta } from "../db/queries/outbox";

const BASE_URL = "https://journal.example.workers.dev"; // your mock server
const CURSOR_KEY = "last_pulled_at";

export type SyncResult = { pulled: number; pushed: number; failed: number };

let inFlight: Promise<SyncResult> | null = null;

/**
 * Run-lock. Foreground, network-regained, manual button and the background task
 * all call this; without the lock two runs push the same outbox row twice.
 */
export function kick(): Promise<SyncResult> {
  inFlight ??= run().finally(() => {
    inFlight = null;
  });
  return inFlight;
}

async function run(): Promise<SyncResult> {
  const pulled = await pull();          // remote first, so local wins on conflict
  const { pushed, failed } = await push();
  return { pulled, pushed, failed };
}

async function pull() {
  const cursor = (await getMeta(db, CURSOR_KEY)) ?? "0";
  const response = await fetch(`${BASE_URL}/entries?since=${cursor}`);
  if (!response.ok) throw new Error(`pull failed: ${response.status}`);

  const { entries, serverTime } = (await response.json()) as {
    entries: {
      id: string;
      title: string;
      body: string;
      mood: number | null;
      created_at: number;
      updated_at: number;
      deleted_at: number | null;
    }[];
    serverTime: number;
  };

  await db.withTransactionAsync(async () => {
    for (const remote of entries) {
      // Last-write-wins by updated_at, and never clobber a row with unsent local
      // edits — that WHERE clause is the entire conflict policy.
      await db.runAsync(
        `INSERT INTO entries (id, title, body, mood, created_at, updated_at, deleted_at, remote_id, dirty)
         VALUES (?, ?, ?, ?, ?, ?, ?, ?, 0)
         ON CONFLICT (id) DO UPDATE SET
           title      = excluded.title,
           body       = excluded.body,
           mood       = excluded.mood,
           updated_at = excluded.updated_at,
           deleted_at = excluded.deleted_at
         WHERE entries.dirty = 0 AND entries.updated_at < excluded.updated_at`,
        remote.id,
        remote.title,
        remote.body,
        remote.mood,
        remote.created_at,
        remote.updated_at,
        remote.deleted_at,
        remote.id
      );
    }
    await setMeta(db, CURSOR_KEY, String(serverTime));
  });

  return entries.length;
}

async function push() {
  const batch = await claimBatch(db, 25);
  let pushed = 0;
  let failed = 0;

  for (const item of batch) {
    try {
      // PUT on the client-generated ULID: replaying it is a no-op, so a lost
      // response costs nothing. That is what makes retries safe.
      const response = await fetch(`${BASE_URL}/entries/${item.entity_id}`, {
        method: item.op === "delete" ? "DELETE" : "PUT",
        headers: { "content-type": "application/json", "idempotency-key": item.entity_id },
        body: item.op === "delete" ? undefined : item.payload,
      });

      if (response.ok) {
        await db.withTransactionAsync(async () => {
          await completeItem(db, item.id);
          // Only clear `dirty` if no newer edit is still queued for this row.
          await db.runAsync(
            `UPDATE entries SET dirty = 0
             WHERE id = ? AND NOT EXISTS (SELECT 1 FROM outbox WHERE entity_id = ?)`,
            item.entity_id,
            item.entity_id
          );
        });
        pushed++;
      } else if (response.status >= 400 && response.status < 500) {
        // The server will never accept this. Dead-letter it and surface it.
        await failItem(db, item, `HTTP ${response.status}`, { permanent: true });
        failed++;
      } else {
        await failItem(db, item, `HTTP ${response.status}`); // 5xx: retry with backoff
        failed++;
      }
    } catch (cause) {
      await failItem(db, item, String(cause)); // offline: stay queued, no drama
      failed++;
    }
  }

  return { pushed, failed };
}

import { useCallback, useEffect } from "react";
import { AppState } from "react-native";

import { useLockStore } from "../stores/lockStore";
import { useSettingsStore } from "../stores/settingsStore";

export function useAppLock() {
  const locked = useLockStore((state) => state.locked);
  const lock = useLockStore((state) => state.lock);
  const unlock = useLockStore((state) => state.unlock);
  const enabled = useSettingsStore((state) => state.biometricLock);
  const graceMs = useSettingsStore((state) => state.lockAfterMs);

  useEffect(() => {
    if (!enabled) {
      unlock();
      return;
    }

    let leftAt: number | null = null;
    const subscription = AppState.addEventListener("change", (state) => {
      if (state === "active") {
        if (leftAt !== null && Date.now() - leftAt >= graceMs) lock();
        leftAt = null;
      } else {
        // "inactive" fires for the app switcher too — that is the moment the
        // OS takes the snapshot, so treat it as leaving.
        leftAt ??= Date.now();
      }
    });

    return () => subscription.remove();
  }, [enabled, graceMs, lock, unlock]);

  const authenticate = useCallback(async () => {
    const capable =
      (await LocalAuthentication.hasHardwareAsync()) &&
      (await LocalAuthentication.isEnrolledAsync());

    if (!capable) {
      unlock(); // no enrolled biometrics: never brick the user out of their data
      return true;
    }

    const result = await LocalAuthentication.authenticateAsync({
      promptMessage: "Unlock your journal",
      fallbackLabel: "Use passcode",
    });
    if (result.success) unlock();
    return result.success;
  }, [unlock]);

  return { locked: enabled && locked, authenticate };
}

    await Sharing.shareAsync(file.uri, {
      mimeType: format === "json" ? "application/json" : "text/markdown",
      dialogTitle: "Export journal",
    });
  }

  return file.uri;
}

function toMarkdown(entry: Entry) {
  const tags = entry.tags.map((tag) => `#${tag}`).join(" ");
  return [
    `## ${entry.title || "Untitled"}`,
    `*${entry.createdAt.toLocaleString()}*${entry.mood ? ` · mood ${entry.mood}/5` : ""}`,
    "",
    entry.body,
    tags && `\n${tags}`,
  ]
    .filter(Boolean)
    .join("\n");
}

Failure modes to experience deliberately

  1. Migration that drops data. Write a bad v2 migration (a table recreate without a backfill), run it against real data, watch entries vanish. Then write the correct one. This teaches you why user_version gating and backfills matter more than any ORM feature.
  2. FTS drift. Update a row without the trigger in place; search returns the stale text. Learn to rebuild the FTS index.
  3. Duplicate sync. Kick the sync engine twice concurrently with no mutex. Watch the server get two copies. Add a run-lock.
  4. Background task that never fires. Register on iOS, wait a day, note it fired zero or once. Understand that background execution is a hint, not a schedule — your app must still work if it never runs.
  5. Notification permission denied. Deny it, then try to schedule. Handle it gracefully with a "open Settings" path via Linking.
  6. Blocked JS thread. Run a large synchronous query on the JS thread during a scroll; watch FPS collapse. Move it to an async call or paginate.
  7. App switcher leak. Lock the app but forget to blur the snapshot — the journal is readable in the task switcher. Fix it.
